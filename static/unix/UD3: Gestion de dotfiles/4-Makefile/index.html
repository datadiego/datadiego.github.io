    Makefile

    Ahora mismo tienes un directorio de dotfiles funcional, cuando tengas que recrear tu equipo:

    1. Instalas tu distro
    2. Clonas tu repositorio de dotfiles
    3. Instalas las dependencias con tus .sh en el directorio de scripts
    4. Haces stow de las aplicaciones que necesitas, borrando los directorios que necesites para que funcione

    Sin embargo, podemos mejorarlo. La idea es que pasemos de esos 4 pasos a:

    1. Instalas la distro
    2. Clonas el repositorio de dotfiles
    3. Lanzas un comando

    Y todo se instale y se haga stow de lo necesario sin que tengas que preocuparte de nada mas.

    Para eso usaremos el comando make, que nos permite automatizar diferentes tareas, ejecutar scripts y orquestar más fácilmente esto.

    Preparando el banner

    En tu repositorio de dotfiles, crea un archivo llamado logo usando figlet:

    figlet -f slant dotfiles > logo

    Puedes poner el texto y fuente que prefieras, esto solo es estético.

    Creando un Makefile

    Para poder usar make en el proyecto necesitaremos un archivo llamado Makefile en nuestra raiz del directorio dotfiles, la estructura final del proyecto será asi:

    .
├── bash
│   └── .bashrc
├── logo
├── Makefile
├── scripts
│   ├── common.sh
│   ├── dev-tools.sh
│   ├── gaming.sh
│   ├── git-configuration.sh
│   └── hacking-tools.sh
└── zed
    └── .config
        └── zed
            ├── keymap.json
            └── settings.json

    Copia este Makefile en tu proyecto:

    SHELL := /bin/bash

PACKAGES := bash zed
.PHONY: help install stow unstow clean

help:
    @cat logo
    @grep -E '^[a-zA-Z0-9_-]+:.*?## .*$$' $(MAKEFILE_LIST) | awk 'BEGIN {FS = ":.*?## "}; {printf "  \033[36m%-15s\033[0m %s\n", $$1, $$2}'

install: ## Instalación completa
    @echo "Ejecutando scripts/common.sh..."
    @bash scripts/common.sh
    @bash scripts/dev-tools.sh
    @bash scripts/hacking-tools.sh
    @bash scripts/gaming.sh
    @$(MAKE) stow

stow: ## Enlazar los dotfiles con GNU stow
    @rm -f ~/.bashrc
    @rm -rf ~/.config/zed
    @for pkg in $(PACKAGES); do \
        echo "Stowing $$pkg..."; \
        stow -S "$$pkg"; \
    done

unstow: ## Desenlazar los dotfiles
    @for pkg in $(PACKAGES); do \
        echo "Unstowing $$pkg..."; \
        stow -D "$$pkg"; \
    done

clean: ## Eliminar archivos generados
    @rm -f *.zip
    @echo "Archivos generados eliminados"

    Si ahora lanzas el comando make en el directorio de tus dotfiles:

    ❯ make
       __      __  _____ __
  ____/ /___  / /_/ __(_) /__  _____
 / __  / __ \/ __/ /_/ / / _ \/ ___/
/ /_/ / /_/ / /_/ __/ / /  __(__  )
\__,_/\____/\__/_/ /_/_/\___/____/

  install         Instalación completa
  stow            Enlazar los dotfiles con GNU stow
  unstow          Desenlazar los dotfiles
  clean           Eliminar archivos generados

    Esto nos permitirá ejecutar make install para instalar y hacer stow de todo.

    Antes de hacerlo, vamos a entender como funciona el Makefile, para que puedas ajustarlo a tu proyecto.

    Entendiendo el Makefile

    Un Makefile no es más que una serie de reglas que le dicen a make qué tiene que hacer. Cada regla tiene esta forma:

    objetivo: dependencias
    comandos
    • objetivo: es el nombre de la tarea, como install o stow.
    • dependencias: otras tareas o archivos que deben ejecutarse o existir antes de poder hacer esta.
    • comandos: las líneas de shell que se ejecutan. Deben estar indentadas con un tabulador (la tecla Tab), nunca con espacios, make es muy estricto con esto y fallará si usas espacios.

    Cuando ejecutas make sin argumentos, ejecuta el primer objetivo que encuentre, que en nuestro caso es help. Por eso al lanzar make a secas ves el banner y el menú de objetivos.

    Variables

    En la parte superior definimos las variables que usaremos más adelante en el archivo:

    SHELL := /bin/bash

PACKAGES := bash zed
    • SHELL: por defecto make ejecuta los comandos con /bin/sh. Al forzar que use /bin/bash nos aseguramos de que los comandos se comporten igual que en nuestros scripts, por si más adelante necesitamos alguna sintaxis propia de bash.
    • PACKAGES: la lista de aplicaciones que gestionamos con stow. Para usar el valor de una variable la referenciamos con $(PACKAGES), que se sustituye por bash zed. Tendrás que añadir aqui el nombre del directorio de otros dotfiles que añadas a tu proyecto para que make haga stow.

    Objetivos phony

    .PHONY: help install stow unstow clean

    make asume por defecto que cada objetivo es un archivo. Imagina que en el directorio existe un archivo llamado clean, entonces make clean pensaría que ya está hecho (el archivo existe, no puede estar más nuevo que sus dependencias) y no ejecutaría nada. Al declarar los objetivos como .PHONY le decimos a make que no son archivos y que los ejecute siempre.

    El objetivo help

    help:
    @cat logo
    @grep -E '^[a-zA-Z0-9_-]+:.*?## .*$$' $(MAKEFILE_LIST) | awk 'BEGIN {FS = ":.*?## "}; {printf "  \033[36m%-15s\033[0m %s\n", $$1, $$2}'

    Aunque parece complicado, en realidad hace dos cosas:

    1. @cat logo: imprime el banner que generamos con figlet.
    2. Busca dentro del propio Makefile todas las líneas que sigan el patrón objetivo: ... ## descripción, extrae el nombre del objetivo y su descripción con awk, y las imprime alineadas en una columna de color cian.

    Aquí aparecen tres cosas importantes que se repiten en el resto del archivo:

    • El prefijo @ al inicio de cada comando hace que make no muestre el comando que ejecuta, solo muestre su resultado. Si lo quitas, verás cada comando antes de ejecutarse, lo que puede venir bien para depurar.
    • Escribimos $$ en lugar de $ dentro de los comandos: make interpreta $ como variables, así que con $$ le decimos que deje pasar un $ para que la shell sea quien lo interprete.
    • $(MAKEFILE_LIST) es una variable especial de make que contiene la lista de Makefiles que se están leyendo, es decir, nuestro Makefile. Sin ella, grep no sabría dónde buscar.

    Por eso, si un objetivo tiene un ## con una descripción después de los dos puntos, aparecerá en el menú de help automáticamente. No tienes que tocarlo.

    El objetivo install

    install: ## Instalación completa
    @echo "Ejecutando scripts/common.sh..."
    @bash scripts/common.sh
    @bash scripts/dev-tools.sh
    @bash scripts/hacking-tools.sh
    @bash scripts/gaming.sh
    @$(MAKE) stow

    Este objetivo es el más simple de entender: avisa de lo que va a hacer, luego ejecuta los cuatro scripts de instalación que creaste en la parte anterior, y al terminar llama a $(MAKE) stow.

    Fíjate en que usamos $(MAKE) en lugar de escribir make directamente. Esto hace que la llamada recursiva use la misma versión y los mismos flags con los que se invocó. Es la forma recomendada de llamar a make desde dentro de un Makefile.

    El resultado es que toda nuestra instalación se reduce a un único comando: make install.

    El objetivo stow

    stow: ## Enlazar los dotfiles con GNU stow
    @rm -f ~/.bashrc
    @rm -rf ~/.config/zed
    @for pkg in $(PACKAGES); do \
        echo "Stowing $$pkg..."; \
        stow -S "$$pkg"; \
    done

    Este objetivo ataca el paso manual que quedaba pendiente, el de "borrar los directorios necesarios para que funcione":

    1. rm -f ~/.bashrc y rm -rf ~/.config/zed borran la configuración existente de esas aplicaciones. Esto es necesario porque, como viste en la parte de stow, stow no sobrescribe archivos que no haya creado él mismo. Si ya tienes un .bashrc real, fallará al intentar enlazarlo.
    2. El for recorre $(PACKAGES), en este caso bash zed, y por cada uno ejecuta stow -S "$pkg" para crearlo enlazado.
    3. Los \ al final de cada línea son continuaciones de línea: para make, el bucle entero es una sola línea de shell. Si los quitaras, make ejecutaría cada línea por separado y el bucle no funcionaría.

    Si en el futuro añades una aplicación nueva a tus dotfiles, solo tendrás que: 1. Añadir su carpeta a PACKAGES. 2. Si ya tienes configuración previa de esa aplicación en el sistema, añadir su borrado justo antes del for. Como hemos hecho con bashrc o zed

    Así de simple puedes adaptarlo a tu proyecto.

    Los objetivos unstow y clean

    unstow: ## Desenlazar los dotfiles
    @for pkg in $(PACKAGES); do \
        echo "Unstowing $$pkg..."; \
        stow -D "$$pkg"; \
    done

clean: ## Eliminar archivos generados
    @rm -f *.zip
    @echo "Archivos generados eliminados"
    • unstow hace exactamente lo mismo que stow pero con stow -D, que deshace los enlaces. Te vendrá bien si quieres dejar de usar un dotfile o antes de hacer una limpieza.
    • clean es un objetivo genérico para borrar archivos que se generen durante el proceso, como los .zip que hayas descargado para instalar un tema o una fuente. Lo ajustarás según lo que necesite tu proyecto.

    Probándolo

    Ahora ya entiendes qué hace cada parte. En tu equipo, ejecuta:

    make install

    make ejecutará los cuatro scripts de instalación y después hará stow de bash y zed automáticamente.

    Si algo no funciona, quita los @ de los comandos del objetivo que falla y vuelve a ejecutarlo: verás exactamente qué comando está fallando, que es el primer paso para corregirlo.

    Con esto ya tienes tu instalación totalmente automatizada, pasando de los 4 pasos manuales del inicio a un único make install.
