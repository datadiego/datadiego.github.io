    Automatizar instalación

    Esta parte es la más sencilla, ya sabes usar el gestor de paquetes, y puede que hayas instalado aplicaciones mediante otros sistemas como flatpak, o scripts.

    shell scripts

    La idea de un shell script es bastante simple, cualquier comando de bash que has dado hasta puede escribirse en un archivo, y ejecutarlo todo después, por ejemplo:

    /tmp/test took 1m37s
❯ cat script.sh
echo "comenzando script"

mkdir dirA
mkdir dirB

seq 0 10

echo "hola mundo" > hola.txt
echo "hola linux" > linux.txt

cp hola.txt dirA
cp linux.txt dirB

echo "terminando script"

tree .

    Podemos darle permisos:

    chmod +x script.sh

    Y ejecutarlo:

    /tmp/test
❯ ./script.sh
comenzando script

└── script.sh

    De la misma forma, puedes crear un script que instale todo lo necesario.

    Automatizando instalaciones

    No hay que aprender mucho para crear estos scripts, ya conoces los comandos para instalar, primero pruebalos a mano, y una vez compruebes que instalan correctamente, añadelos a tu script para que en otro equipo puedas hacerlo todo de golpe.

    Sin embargo, si tu script simplemente es algo como esto:

    sudo dnf install sqlite3
sudo dnf install nvim
sudo dnf install tldr
sudo dnf install btop

    Tendrás que confirmar cuatro veces pulsando Y que quieres instalarlo, esto puedes evitarlo con la flag -y, que autoacepta la instalación:

    sudo dnf install sqlite3 -y
sudo dnf install nvim -y
sudo dnf install tldr -y
sudo dnf install btop -y

    Ten en cuenta además que puedes instalar múltiples paquetes en una sola linea:

    sudo dnf install -y sqlite3 nvim tldr btop

    Y que si la linea crece demasiado, quizá es mejor separarlo en multiples lineas:

    sudo dnf install -y \
sqlite3 \ 
nvim \
tldr \
btop

    Solo asegúrate de poner \ en cada linea si debajo hay otra, la última no la lleva.

    Estructura en el proyecto

    Suelo crear un directorio llamado scripts para guardar ahi todos los scripts de instalación que necesita el proyecto, es buena idea dividir en varios cuando tu configuración crece, por ejemplo:

    .
├── bash
│   └── .bashrc
├── scripts
│   ├── common.sh
│   ├── dev-tools.sh
│   ├── gaming.sh
│   └── hacking-tools.sh
└── zed
    └── .config
        └── zed
            ├── keymap.json
            └── settings.json
    • common.sh: herramientas comunes para el funcionamiento del sistema y aplicaciones que siempre quiero.
    • dev-tools.sh: herramientas para desarrollar software.
    • hacking-tools.sh: herramientas de hacking y ciberseguridad
    • gaming.sh: juegos y plataformas como steam

    Esto te permitirá personalizar más cada equipo, quizá uno solo lo usarás para desarrollo y hacking y otro solo para gaming. En ambos tendrás instalado common.sh, y luego completarás con el script que necesites.
