    Shell scripting

    Ya has usado bastante la terminal y conoces bastantes comandos. Saber usarla te permite empezar a hacer más cosas.

    En concreto, puedes usar lo que sabes para crear shell scripts. Los shell scripts son la practica de escribir una serie de comandos en un archivo, para que tu shell las interprete y sean ejecutados automáticamente.

    Si sabes usar la terminal, podrás hacer mucho más fácilmente:

    • Gestión compleja de archivos y directorios
    • Instalar software
    • Hacer backups
    • Monitorear sistemas
    • Automatizar tareas repetitivas

    Esto además te permitirá extender los comportamientos de tu shell con scripts que pueden ejecutarse desde cualquier lado.

    Un ejemplo simple

    Normalmente uso mucho /tmp para experimentos, si necesito probar cosas, me voy a ese directorio, creo un directorio llamado test, y luego dentro de el empiezo a trabajar.

    Hacer un script de esto es bastante sencillo, solo crea un archivo con:

    rm -rf /tmp/test
mkdir /tmpt/test
cd /tmp/test

    Dale permisos:

    chmod +x lab.sh

    Y ejecútalo:

    ./lab.sh

    Modifica tu laboratorio como prefieras, puedes dejarte bastantes cosas preconfiguradas:

    rm -rf /tmp/test
mkdir /tmp/test
cd /tmp/test || return
git init
echo "hola mundo" > hello

    shebang

    Ejecutar scripts

    Ahora mismo para ejecutar el script debes poner toda la ruta hasta llegar al mismo, o estar situado en el mismo directorio, por ejemplo:

    ~/mis_scripts/lab.sh

    Esto también seria válido:

    cd mis_scripts
./lab.sh

    Pero lo ideal sería poder lanzar lab desde cualquier sitio y ejecutarlo.

    Tenemos varias opciones para lograr esto:

    Llevando el script a un directorio en $PATH

    El $PATH son las rutas que nuestra shell busca para encontrar ejecutables:

    ~
❯ echo $PATH
/home/datadiego/.druk/bin /home/datadiego/.local/bin /usr/local/bin /usr/bin

    Si movemos el script a cualquiera de estos directorios podremos ejecutarlo desde cualquier sitio en la terminal, la más común es /home/tu_usuario/.local/bin:

    sudo mv lab.sh ~/.local/bin/

    Y ahora podrás ejecutarlo con lab.sh desde cualquier lado. Si prefieres que sea lab a secas, renombra el script quitandole el .sh.

    Si no tienes ~/.local/bin en tu $PATH, añadelo:

    En Bash

    Añade esto en tu bashrc:

    export PATH="$HOME/.local/bin:$PATH"
    En Fish

    Busca una linea como esta:

    fish_add_path /home/datadiego/.local/bin /home/datadiego/bin

    O añádela, bien sea en tu configuración principal, o en el directorio de conf.d, a mi me gusta tener un archivo llamado env.fish ahí para establecer todos mis paths y variables de entorno.

    Como una función

    Dependiendo de tu shell, simplemente puedes crear una función y añadirla a tu archivo de configuración principal, o al directorio que usa para cargar todo lo que metas ahí.

    En Bash

    Un archivo en ~.bashrc.d:

    lab() {
  rm -rf /tmp/test
  mkdir /tmp/test
  cd /tmp/test
}
    En Fish

    Un archivo en .config/fish/functions:

    function lab
    rm -rf /tmp/test
    mkdir /tmp/test
    cd /tmp/test
    git init
    echo "hola mundo" > hello
end
