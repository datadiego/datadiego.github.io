    Permisos

    Ya hemos visto cómo diferentes usuarios por defecto solo tienen permiso para leer archivos en sus directorios home.

    Podemos cambiar estos permisos y hacer que otros tengan acceso, o limitarlos según prefiramos.

    Ver los permisos de un archivo o directorio

    Llevamos un tiempo usando ls -la en el sistema, pero no hemos hablado de todos los datos que nos da, por ejemplo, en este archivo:

    pruebas@fedora:~$ ls -la .bashrc
-rw-r--r--. 1 pruebas pruebas 522 ene 16  2026 .bashrc

    Nos da los siguientes datos:

    -rw-r--r--.  1  pruebas  pruebas  522  ene 16 2026  .bashrc
│└───┬────┘  │     │        │       │          │          │
│    │       │     │        │       │          │          └─ Nombre
│    │       │     │        │       │          └─ Fecha
│    │       │     │        │       └─ Tamaño: 522 bytes
│    │       │     │        └─ Grupo propietario
│    │       │     └─ Usuario propietario
│    │       └─ Enlaces físicos
│    │   
│    └─ Tipo + permisos
└─ Tipo de archivo

    Vamos a fijarnos en la parte de permisos:

    -rw-r--r--.
│└┬┘└┬┘└┬┘
│ │  │  │
│ │  │  └──── Otros
│ │  └─────── Permisos de grupo
│ └────────── Permisos de propietario
└──────────── Tipo de archivo

    Es decir:

                 r    w    x
           leer escribir ejecutar
             │     │      │
Propietario  r     w      -     → rw-
Grupo        r     -      -     → r--
Otros        r     -      -     → r--

    El propietario puede leer y escribir, el grupo pruebas puede leer, y otros (cualquier usuario que no sea el propietario y no esté en el grupo pruebas) también puede leerlo.

    Pero entonces, si bashrc tiene permisos de lectura para que otros lo puedan leer, ¿por que sucede esto?

    ~ took 2s
❯ cat /home/pruebas/.bashrc
cat: /home/pruebas/.bashrc: Permiso denegado

~
❯ sudo ls -la /home/pruebas/.bashrc
-rw-r--r--. 1 pruebas pruebas 522 ene 16  2026 /home/pruebas/.bashrc

    La respuesta es simple, para llegar a bashrc debemos atravesar /home/pruebas/ y si miramos los permisos:

    ~
❯ ls -l /home
drwx------@ - datadiego 18 sep 11:38 datadiego
drwx------@ - pruebas   18 sep 11:47 pruebas

    Solo pruebas puede leer, escribir y ejecutar cosas en su directorio, lo mismo pasa con datadiego

    Cambiando permisos de un directorio

    Vamos a cambiar los permisos del directorio /home/pruebas/ para que otros puedan leerlo, pero no editarlo:

    ~
❯ sudo chmod 755 /home/pruebas
[sudo] contraseña para datadiego:

~ took 5s
❯ ls -l /home
drwx------@ - datadiego 18 sep 11:38 datadiego
drwxr-xr-x@ - pruebas   18 sep 11:47 pruebas

    Ahora deberíamos poder navegar y leer desde tu usuario el directorio del usuario pruebas:

    ~
❯ pwd
/home/datadiego

~
❯ cd /home/pruebas

/home/pruebas🔒
❯ head .bashrc -n 4
# .bashrc

# Source global definitions
if [ -f /etc/bashrc ]; then

    Pero no podemos escribir en el:

    /home/pruebas🔒
❯ echo "hola desde otro user" > hola
warning: An error occurred while redirecting file 'hola'
open: Permiso denegado

    Notación de permisos

    Y entonces, en sudo chmod 755 /home/pruebas ¿Que es 755?

    No es más que una forma numérica de representar permisos usando octal (base 8) donde 7 es el valor máximo.

    La idea es que cada permiso tiene un valor:

    r = 4
w = 2
x = 1

    Y en realidad, solo debes memorizar esos valores, el resto de permisos que combinan, no es más que la suma:

    r-- = 4 + 0 + 0 = 4
r-x = 4 + 0 + 1 = 5
rw- = 4 + 2 + 0 = 6
rwx = 4 + 2 + 1 = 7

    También puedes usar una calculadora de permisos para entenderlo mejor.

    Cambiando el propietario y grupo

    Hasta ahora hemos visto los permisos rwx de las columnas propietario y grupo, pero chmod solo cambia los permisos, no los dueños. Para eso usamos otros dos comandos:

    • chown cambia el propietario (y opcionalmente el grupo) de un archivo o directorio.
    • chgrp cambia solo el grupo propietario.

    La sintaxis básica es:

    chown <usuario> <archivo>
chown <usuario>:<grupo> <archivo>
chgrp <grupo> <archivo>

    Ambos pueden usar -R para aplicar el cambio de forma recursiva a todos los archivos y subdirectorios de una carpeta.

    Verás estos comandos en acción más adelante, sobre todo al gestionar servidores o proyectos compartidos.

    En la práctica

    Durante el curso solo tendrás que hacer una cosa que tenga que ver con permisos, y es dar permisos de ejecución a scripts y programas, por ejemplo:

    /tmp/test
❯ cat programa
echo "iniciando cuenta"
seq 0 5
echo "cuenta finalizada"

/tmp/test
❯ ls
.rw-r--r--@ 57 datadiego 18 sep 12:20 programa

/tmp/test
❯ ./programa
fish: Comando desconocido. ‘./programa’ existe pero no es un archivo ejecutable.

    Como ves, podemos leer y editar el archivo, pero si intentamos ejecutarlo, no tenemos permiso.

    La forma más rápida de editar permisos sin tener que lidiar con octal es usar esta otra forma:

    /tmp/test
❯ chmod +x programa

/tmp/test
❯ ./programa
iniciando cuenta
0
1
2
3
4
5
cuenta finalizada

/tmp/test
❯ ls
.rwxr-xr-x@ 57 datadiego 18 sep 12:20 programa

    Ahora cualquier usuario con acceso a /tmp/test puede ejecutar este archivo:

    /tmp/test
❯ su pruebas
Contraseña:
pruebas@fedora:/tmp/test$ ./programa
iniciando cuenta
0
1
2
3
4
5
cuenta finalizada
