    Como utilizar IA de forma efectiva

    Se ha escrito mucho sobre como utilizar estas herramientas de forma efectiva. Al ser una tecnología nueva, cada dia veréis nuevos posts que hablan de como usarlas, así que puede llegar a marear bastante.

    La realidad

    No hay consenso.

    Cada uno las utiliza de forma distinta, con mayor o menor éxito. Al ser una herramienta que además abre la edición de código a personas sin un conocimiento previo de programación, las técnicas varían según su nivel de experiencia.

    Debido a esto, vamos a distinguir varias formas de utilizarla. Partiendo desde la que más delega el control a estos agentes, hasta la que más se acerca a la programación tradicional.

    Vibecoding

    vibecoding hace referencia a la práctica de usar agentes de IA para escribir código, en el que el usuario delega al agente todas las decisiones sobre cómo debería crear la aplicación.

    El usuario no decide la estrategia de desarrollo, la estructura de proyecto, herramientas, librerías o frameworks a utilizar. El agente decide todas las decisiones mientras que el desarrollador solo pide que quiere que haga la aplicación.

    Puede ser útil para quien no tiene experiencia y no quiere aprender programación, para crear herramientas internas, y para configurar algunos aspectos de Linux.

    El problema de esto es que tienes cero control sobre qué se está haciendo, y es difícil que ante una aplicación compleja el agente no arregle algo sin romper otra cosa, o acabar con lineas y funciones de código muertas que no se ejecutan nunca.

    No indicar nada acerca de la infraestructura de tu aplicación, ni de las librerías a usar significa que tomará generalmente el camino más rápido y simple posible, resultando en una aplicación que parece funcionar, pero no necesariamente que haga lo esperado, algunos ejemplos:

    • La aplicación se ejecuta correctamente, pero solo si el usuario hace siempre las cosas correctamente, ante cualquier caso que no se contempla, la aplicación falla.
    • La aplicación parece funcionar, pero solo es un frontend bonito, no hay forma de interactuar con ella ni de almacenar o recuperar datos.
    • La aplicación parece funcionar, y nos permite interactuar con ella como si hubiese un backend, pero solo se guarda en memoria (en caso de una aplicación de escritorio) o en localStorage (en el caso de una aplicación web), de forma que al cerrar la aplicación los datos se pierden.
    • La aplicación funciona, tiene un backend, y existe una base de datos para almacenar los datos, pero al no especificar cual, se ha optado por un DaaS con una configuración predeterminada e insegura, el camino más rápido y simple posible, y haciendo un vendor lock-in a un servicio de terceros.

    IA como motor de desarrollo

    Muchos usuarios delegan por completo el desarrollo a los agentes de IA.

    En estos casos, suelen tener diferentes agentes para cada tarea:

    • Agente de planificación: Este agente se encarga de planificar la estrategia de desarrollo.
    • Agente de codificación: Este agente se encarga de escribir el código.
    • Agente de revisión: Este agente se encarga de revisar y corregir el código.
    • Agente de testing: Este agente se encarga de probar el código.
    • Agente de despliegue: Este agente se encarga de desplegar el código en producción.

    Es una manera de trabajar muy costosa, no solo a nivel de infraestructura, sino también monetariamente.

    Por otro lado, a dia de hoy, delegar por completo el desarrollo a agentes resultará en menos (o ningún) control sobre el código producido, de forma que ante un fallo o error, sólo los agentes podrán solucionarlo, o resolverlo con humanos se volverá una tarea demasiado costosa.
