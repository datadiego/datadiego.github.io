    Shell

    La shell es tu intérprete de comandos.

    Cuando escribes un comando en la terminal y pulsas enter, tu shell es quien hace de intermediario para encontrar ese programa, y ejecutarlo usando el kernel.

    La terminal por si sola lo único de lo que se encarga es de darte una interfaz de entrada y salida de texto para un proceso, mediante la shell. Y permite interpretar diferentes combinaciones de teclas para algunas funciones especiales.

    Tienes diferentes shells, y diferentes terminales que puedes instalar y usar.

    Que sucede al lanzar un comando

    El orden de eventos, de manera simplificada, seria asi:

    flowchart LR
    comando["ls -la"] --> q0{"¿Es builtin?"}

    q0 -- sí --> shell["Lo ejecuta la shell"]
    q0 -- no --> buscar["Buscar en los directorios de $PATH"]

    buscar --> p1["/home/user/.local/bin"]
    buscar --> p2["/usr/local/bin"]
    buscar --> p3["/usr/bin"]

    p1 --> encontrado{"¿Encontrado?"}
    p2 --> encontrado
    p3 --> encontrado

    encontrado -- sí --> exec["Ejecutar el programa"]
    encontrado -- no --> error["command not found"]

    Los builtins son comandos internos que tiene la shell, dependiendo de la shell tendras diferentes.

    Los comandos externos son binarios ejecutables que están en tu $PATH.

    $PATH son los directorios donde tu shell busca binarios que pueda ejecutar, puedes añadir nuevas rutas a tu $PATH.

    Puedes comprobar que si un comando es interno o externo con type:

    ~
❯ type echo
echo es un comando interno

~
❯ type mkdir
mkdir es /usr/bin/mkdir

❯ type ls
ls es un alias de `ls -la'

    En tu caso, ls te devolverá que es un comando interno, más adelante verás que es un alias.

    Configurando tu shell

    Ahora mismo estás usando bash como shell. Puedes modificar tu shell editando el archivo de tu home ~/.bashrc, tendrás algo similar a esto:

    # Source global definitions
if [ -f /etc/bashrc ]; then
  . /etc/bashrc
fi

# User specific environment
if ! [[ "$PATH" =~ "$HOME/.local/bin:$HOME/bin:" ]]; then
  PATH="$HOME/.local/bin:$HOME/bin:$PATH"
fi
export PATH

# User specific aliases and functions
if [ -d ~/.bashrc.d ]; then
  for rc in ~/.bashrc.d/*; do
    if [ -f "$rc" ]; then
      . "$rc"
    fi
  done
fi
unset rc

    Este archivo se ejecuta cada vez que abres una terminal, y carga la configuración que escribas aquí.

    El bloque:

    if [ -f /etc/bashrc ]; then
  . /etc/bashrc
fi

    Son las definiciones globales, se cargan desde el archivo /etc/bashrc, no modifiques este archivo si no tienes un buen motivo de hacerlo. Tampoco quites ese bloque de tu ~/.bashrc.

    El siguiente bloque:

    # User specific environment
if ! [[ "$PATH" =~ "$HOME/.local/bin:$HOME/bin:" ]]; then
  PATH="$HOME/.local/bin:$HOME/bin:$PATH"
fi
export PATH

    Define el PATH para aplicaciones que solo puede usar tu usuario. Puedes meter tus scripts ahí para ejecutarlos desde la terminal como un comando. El path por defecto para estas aplicaciones es ~/.local/bin

    Por último:

    # User specific aliases and functions
if [ -d ~/.bashrc.d ]; then
  for rc in ~/.bashrc.d/*; do
    if [ -f "$rc" ]; then
      . "$rc"
    fi
  done
fi
unset rc

    Carga todos los alias y funciones que crees como archivos en el directorio ~/.bashrc.d, te servirá para mantener tu ~/.bashrc más ordenado cuando empiece a ser un archivo muy grande. Por ahora, déjalo, configuraremos todo desde este archivo, más adelante podrás dividir tu configuración en múltiples usando este directorio.

    Vamos a aprender dos cosas básicas sobre como configurar nuestra shell, los alias y las funciones.

    alias

    Un alias es una forma de "renombrar" un comando. Esto tiene varios usos.

    Ya sabes que hace el comando ls -la, ¿no seria util poder escribir simplemente la y que se ejecute todo ese comando?

    Añade esto a tu bashrc:

    alias la="ls -la"

    Ahora solo con escribir dos letras, tenemos este comportamiento.

    Recuerda que .bashrc se carga al abrir una terminal, si guardas los cambios y lo pruebas en la misma terminal no funcionará, o bien abres una terminal nueva, o ejecutas source ~/.bashrc para que vuelva a cargar la configuración con el cambio nuevo.

    Cuando avances con la terminal, verás que cada vez escribes comandos más largos o que olvidas con frecuencia, los alias te pueden ayudar mucho a no tener que escribir tanto y minimizar la complejidad de muchas tareas.

    Funciones

    En ocasiones, los alias se quedan cortos y necesitamos ejecutar múltiples comandos.

    Abre una terminal y lanza el comando xdg-open ., se abrirá el gestor de archivos donde estés situado en la terminal. Es un comando útil para muchas tareas, pero tener que escribir todo eso es demasiado trabajo.

    Piensa en que te gustaría escribir para que pudieras abrir el gestor de archivos, quizá open, abrir, o incluso of de open files, muy corto y rápido de escribir.

    Podemos conseguir esto añadiendo un alias en nuestro bashrc:

    alias open="xdg-open ."

    Sin embargo, el comando xdg-open tiene un comportamiento que puede mejorarse, nos deja la terminal bloqueada ejecutando ese proceso hasta que cerremos el gestor de tareas o cortemos la tarea en la terminal con Ctrl + C.

    Para conseguir que se abra sin ocupar nuestra terminal, debemos lanzar este comando:

    nohup xdg-open "$1" >/dev/null 2>&1 &
disown

    No necesitas entender aún que hace todo esto, pero comprobarás que ahora nuestra terminal queda libre y tenemos un gestor de archivos.

    Aqui tenemos dos comandos, unidos con &, para poder ejecutar múltiples comandos con un solo comando deberemos usar una funcion:

    open() {
  nohup xdg-open "$1" >/dev/null 2>&1 &
  disown
}

    Ahora la función open ejecutará esas dos tareas cuando escribamos open ruta_a_abrir, por ejemplo:

    open .
open ~/Descargas
open ~/Documentos/proyecto-1

    Solo necesitas añadir la función a tu bashrc para poder usarla cuando quieras.

    Probando shells alternativos

    Puedes probar otros shells alternativos como zsh o fish. Te darán ayuda adicional y te permiten personalizar tu entorno de shell.

    Fish

    Para instalar fish:

    sudo dnf install fish

    Luego, en tu bashrc añade exec fish para que se ejecute automáticamente cuando inicies sesión:

    exec fish

    Ten en cuenta que tus alias y funciones definidas en bashrc no se heredarán en fish. Tendrás que definirlos en ~/.config/fish/config.fish o dentro de ~/.config/fish/conf.d/.

    Autocompletado

    Fish tiene un sistema de autocompletado integrado que te ayudará a completar comandos y argumentos.

    Cuando escribas un comando te mostrará opciones de autocompletado, para completar el comando pulsa derecha.

    También puedes usar tab para ver flags disponibles en el comando y navegar directorios.

    abbr

    Fish también tiene un sistema de abreviaturas (abbr) que te permite definir comandos personalizados. Por ejemplo:

    abbr -a gl 'git log --oneline'
abbr -a --set-cursor=% sqlall 'sqlite3 test.db "SELECT * FROM %"'

    Lo mejor de abbr es que al contrario que los alias, cuando pulsas espacio después de la abreviatura, aparece el comando completo y puedes editarlo antes de ejecutarlo.

    Además puedes usar % como un marcador de posición para el cursor.
