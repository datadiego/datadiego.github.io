    Variables

    Las variables son contenedores donde almacenamos datos. En JavaScript existen tres formas de declarar variables: var, let y const.

    Declaración de variables

    var

    Es la forma original de declarar variables en JavaScript. Tiene alcance de función, lo que significa que es accesible desde cualquier parte dentro de la función donde fue declarada.

    var nombre = "Carlos";
var edad = 22;

    En la actualidad se recomienda no usar var. Tiene comportamientos confusos como el hoisting y su alcance no es tan predecible.

    let

    Introducida en ES6, let permite declarar variables con alcance de bloque. Solo es accesible dentro del bloque {} donde fue declarada.

    let nombre = "diego"

if(true){
  let nombre = "paco"
  console.log(nombre)
}

console.log(nombre)

if (true) {
  let temp = 10;
  console.log(temp); // 10
}
console.log(temp)

    Al ejecutarlo:

    ❯ node main.js 
paco
diego
10
/tmp/test/main.js:13
console.log(temp)
            ^

ReferenceError: temp is not defined

    const

    También introducida en ES6, const declara una variable cuyo valor no puede ser reasignado. Al igual que let, tiene alcance de bloque.

    const PI = 3.14159;
const CIUDAD = "Valencia";

// PI = 3; // TypeError: Assignment to constant variable.

    const no significa que el valor sea inmutable, solo que la referencia no puede cambiarse. Los objetos y arrays declarados con const pueden modificar sus propiedades.

    const usuario = { nombre: "Ana", edad: 30 };
usuario.nombre = "María"; // Esto funciona

usuario = { nombre: "Diego" } //Error

    Tipo de dato

    Las variables en JavaScript son dialmente tipadas, es decir, no necesitas indicar el tipo de dato al declararlas. El tipo se asigna automáticamente según el valor.

    let texto = "Hola";          // string
let entero = 42;             // number
let decimal = 3.14;          // number
let booleano = true;         // boolean
let vacio = null;            // null
let indefinido = undefined;  // undefined
let objeto = { a: 1 };      // object
let lista = [1, 2, 3];      // array (object)

    Coerción de tipos

    JavaScript es un lenguaje débilmente tipado, lo que significa que intenta convertir los tipos de datos automáticamente cuando realizas operaciones entre tipos diferentes. A esto se le llama coerción de tipos (type coercion).

    let resultado = "5" - 3;    // 2 (el string "5" se convierte a número)
let texto = true + "!";     // "true!" (el boolean se convierte a string)

    No es algo que puedas controlar directamente, ocurre "detrás de escena" y a veces produce resultados inesperados.

    Esta línea de código es un ejemplo famoso de coerción de tipos en acción:

    console.log(('b' + 'a' + + 'a' + 'a').toLowerCase()) //banana

    ¿Que está pasando aqui?

    Si intentamos sumar dos strings:

    > "b" + "a"
'ba'

    Obtenemos un string. Hasta aqui nada extraño. Pero la siguiente operación tiene dos +.

    En javascript, el operador + se puede usar para convertir un string a número:

    > +"123"
123

    Si intentamos convertir algo que no sea un número:

    > +"hola"
NaN

    Devuelve NaN, este valor representa Not a number, sucede cuando intentamos realizar una operación que no es válida entre números. Sin embargo, como estamos sumandolo a varios strings, todo se convierte en un string:

    > "b" + "a" + + "a"
'baNaN'

    Solo nos queda sumar otra "a":

    > "b" + "a" + +"a" + "a"
'baNaNa'

    Y convertirlo a minusculas todo:

    > ("b" + "a" + +"a" + "a").toLowerCase()
'banana'

    ¿Esto te parece raro? Espera:

    > typeof(NaN)
'number'

    Not a Number es... ¿un numero? Sip. JavaScript asignó este tipo a este valor, y ya hay demasiada lógica implementada alrededor de esta decisión como para modificarla.

    No solo eso:

    > 1 == 1
true
> "hola" == "hola"
true
> false == false
true
> NaN == NaN
false

    La comparacion entre dos NaN siempre da false, esto es asi por diseño, no es un bug.

    NaN nunca es igual a nada, ni siquiera a sí mismo. Esto no es una rareza de JavaScript: viene del estándar IEEE 754, que es el que define cómo funcionan los números en coma flotante en casi todos los lenguajes de programación.

    La idea es que NaN no es un valor concreto, sino un marcador de que algo no se pudo calcular. Como no representa un número real, no tiene sentido compararlo con otro valor: el propio estándar especifica que las operaciones de igualdad con NaN deben dar false.

    Por eso, si necesitas comprobar si una operación resultó en NaN, la comparación x === NaN no te sirve. Tienes que usar isNaN() o Number.isNaN():

    var x = NaN;
x === NaN        // false
isNaN(x)         // true
Number.isNaN(x)  // true

    scope (alcance)

    El alcance define dónde es accesible una variable.

    var global = "soy global";

function ejemplo() {
  var local = "soy local";
  let bloque;

  if (true) {
    var dentroFuncion = "var ve el mundo";    // accesible fuera del if
    let dentroBloque = "let solo ve el bloque"; // solo dentro del if
  }

  console.log(dentroFuncion); // funciona
  // console.log(dentroBloque); // ReferenceError
}

ejemplo();
// console.log(local); // ReferenceError
console.log(global);   // funciona
    Palabra clave Alcance Reasignable Elevación (hoisting)
    var Función Sí Sí (valor undefined)
    let Bloque Sí Sí (pero no accesible antes de la declaración)
    const Bloque No Sí (pero no accesible antes de la declaración)

    Hoisting

    JavaScript mueve las declaraciones al inicio de su contexto antes de ejecutar el código.

    console.log(x); // undefined (var hace hoisting con valor undefined)
var x = 10;

// console.log(y); // ReferenceError (let/const hacen hoisting pero no inicializan)
// let y = 5;

    Buenas prácticas

    • Usa const por defecto. Solo cambia a let si necesitas reasignar el valor.
    • Nunca uses var en código moderno.
    • Nombra tus variables de forma clara y descriptiva.
    • Usa camelCase para nombrar variables:
    let nombreUsuario = "Ana";
let edadMaxima = 120;
let esActivo = true;
