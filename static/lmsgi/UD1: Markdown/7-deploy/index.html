    Deploy en github.io

    Github Pages es una herramienta que permite alojar sitios web estáticos directamente desde un repositorio en GitHub totalmente gratis.

    En esta guia verás como desplegar un blog o página personal que usa Hugo como motor para el mismo.

    Repositorio

    Tu repositorio debe tener el siguiente nombre:

    <username>.github.io

    Donde <username> es tu nombre de usuario de GitHub.

    Workflow

    Este es el deploy básico para un sitio creado con hugo:

    on:
  push:
    branches: [master]

permissions:
  contents: write

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          submodules: true
          fetch-depth: 0
      - uses: peaceiris/actions-hugo@v3
        with:
          hugo-version: latest
          extended: true
      - run: hugo --minify
      - uses: peaceiris/actions-gh-pages@v4
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./public
          publish_branch: gh-pages

    Si lo comparas con el workflow del ejemplo anterior, en esta todos los steps son acciones externas ya creadas que realizan las tareas que necesitamos.

    actions/checkout@v4

    La misma que usamos en el anterior para clonar el repositorio en la máquina virtual que levanta la acción.

    peaceiris/actions-hugo@v3

    Esta acción instala todas las dependencias de hugo en el servidor.

    hugo --minify

    El único comando que mandamos manualmente, el mismo que usarías para hacer la build de hugo y generar el html necesario.

    peaceiris/actions-gh-pages

    La acción que manda el directorio que especificamos en publish_dir al hosting de github, debe ser tu html para que cuando entres a tu página de github puedas verla.

    hugo por defecto crea un directorio llamado public cuando ejecutamos su build, otros motores pueden crearlo con otro nombre.

    Configuración de GitHub Pages

    Una vez tengas tu repositorio y el workflow configurado, tendrás que habilitar GitHub Pages en la configuración del repositorio.

    1. Antes de nada, crea una rama llamada gh-pages en tu repositorio de GitHub.

    1. Ve a la pestaña "Settings" de tu repositorio, está a la derecha del todo, junto a Insights.

    1. Ve a la sección "Pages" en el menú de la izquierda.
    2. Busca la sección Build and deployment.
    3. En la opción Source, selecciona Deploy from a branch.
    4. En la opción Branch, selecciona gh-pages y /(root).
    5. Haz clic en Save.

    Mandar cambios

    Una vez tengas todo configurado, cada vez que hagas un push a la rama master del repositorio, el workflow se ejecutará automáticamente y desplegará los cambios en GitHub Pages.
