    Introducción a actions en Github

    Las acciones de github permiten ejecutar código cuando mandamos un cambio a nuestro repositorio.

    Funcionan levantando una máquina virtual con el sistema operativo que prefieras para ejecutar el código.

    Tienen múltiples usos:

    • Ejecutar tests para verificar que el código funciona correctamente
    • Generar documentación automáticamente
    • Compilar código y generar artefactos (binarios, archivos, etc.) que se pueden descargar en el workflow o en el release del repositorio.
    • Generar HTML estático a partir de markdown

    Básicamente, si puedes ejecutarlo localmente, puedes ejecutarlo en Github Actions y hacer lo que quieras con el resultado.

    Despliegues

    Uno de los usos más comunes es desplegar aplicaciones, creando un ciclo de despliegue continuo (CD) que se ejecuta automáticamente cuando mandamos un cambio a nuestro repositorio.

    Estructura

    Las acciones de github se crean en archivos yaml, deben estar dentro del repositorio en .github/workflows/ como en este ejemplo:

    .
├── .git
├── .github
│   └── workflows
│       └── deploy.yml
└── README.md

    En el archivo deploy.yml es donde definimos que queremos que haga la acción.

    Ejemplo de un workflow

    El siguiente archivo .yml genera HTML a partir del archivo README.md del propio repositorio.

    name: Crear HTML

on:
  push:
    branches: [master]

jobs:
  crear-html:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          submodules: true
          fetch-depth: 0
      - name: Instalar dependencias
        run: sudo apt update && sudo apt install -y pandoc
      - name: Build
        run: pandoc README.md --standalone --to html5 -o README.html
      - name: Mostrar HTML
        run: cat README.html

    Trigger

    La primera parte importante:

    on:
  push:
    branches: [master]

    Define el trigger para disparar la acción, en este caso, sólo se dispara cuando llega un push a la rama master. Si tu rama principal en el repositorio es main, no funcionará.

    Acciones externas

    El primer paso:

        steps:
      - uses: actions/checkout@v4
        with:
          submodules: true
          fetch-depth: 0

    Carga una acción desde otro repositorio, esta es una acción creada por los desarrolladores de Github que hace git clone de tu repositorio a la vm levantada por la acción, sin esto, cuando intentásemos ejecutar pandoc sobre nuestro README.md no encontraría el archivo.

    No necesitas saber como está creada la acción externa, sólo que hace y si necesitas pasarle algún tipo de dato extra, suele venir explicado en el propio repositorio de cada acción.

    Encontrarás acciones de todo tipo ya creadas, es raro tener que hacerlo todo de cero.

    Instalar dependencias

    El mismo proceso que harias en tu do tipsistema para instalar las dependencias y generar el html, el binario o el artefacto deseado.

    En nuestro caso necesitamos instalar pandoc, pero podríamos usar otra herramienta de las que hemos estudiado como multimarkdown.

    Si tu proyecto necesita hacer otra cosa, necesitarás instalar las dependencias necesarias, igual que harías en tu sistema.

    Build

    Es el paso en el que generamos el artefacto deseado, en nuestro caso, se genera un HTML con pandoc, pero puede ser compilar nuestro código a un binario, o cualquier otra tarea.

    Mostrar HTML

    Una vez tenemos el artefacto, hacemos lo que necesitemos con el, en este caso simplemente lo mostramos en la propia acción.

    Podríamos enviar el HTML generado a un hosting, subirlo a un artefacto que podemos descargar desde la acción, o llevarlo a la sección de releases de nuestro repositorio, aunque esta sección generalmente es para binarios ejecutables.
