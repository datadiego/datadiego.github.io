    Redis

    Redis es una base de datos en memoria, no está pensada para almacenar persistentemente datos. Es de tipo clave-valor con varios tipos de datos que podemos insertar.

    Es extremadamente rápida, por lo que es usada para cachés, y al no persistir los datos, es perfecta para sesiones de usuario.

    Estructura

    Redis sigue una estructura muy simple:

    Redis
├── clave0
├── clave1
├── clave2
├── clave3
├── clave4
└── clave5

    Aunque cada clave puede almacenar varios datos, como listas o JSON, es muy común que guarden un sólo valor.

    Entorno Docker

    Este entorno es un poco mas complejo, necesitarás:

    .
├── docker-compose.yml
├── entrypoint.sh
└── .env

    El docker-compose relega la inicialización en entrypoint.sh, y hace uso del archivo .env para guardar la contraseña de forma segura:

    services:
  redis:
    image: redis:7
    container_name: redis
    environment:
      REDIS_PASSWORD: ${REDIS_PASSWORD}
    entrypoint: ["/bin/sh", "/entrypoint.sh"]
    volumes:
      - ./entrypoint.sh:/entrypoint.sh:ro
    ports:
      - "6379:6379"

    En cuanto al entrypoint.sh:

    #!/bin/sh
set -e

mkdir -p /etc/redis
cat >/etc/redis/users.acl <<EOF
user default off
user myuser on >${REDIS_PASSWORD} ~* &* +@all
EOF

exec /usr/local/bin/docker-entrypoint.sh redis-server --aclfile /etc/redis/users.acl

    Edita myuser por el nombre de usuario que prefieras.

    Finalmente, el .env con la contraseña:

    REDIS_PASSWORD=password

    Conexión

    De nuevo, necesitarás un cliente redis-cli para poder interactuar con el servicio.

    Desde dentro del contenedor

    Simplemente:

    root@4438218e7970:/data# redis-cli --user myuser --askpass
Please input password: ********
127.0.0.1:6379> ping
PONG

    Desde tu host

    Aunque no es buena idea exponer redis al host y debería estar aislado con el resto de contenedores, en ocasiones puedes querer conectar desde tu propio sistema, también sirve si tienes que conectar a un servidor remoto:

    ❯ redis-cli -h localhost --user myuser --askpass
Please input password: ********
127.0.0.1:6379> ping
PONG

    Cambia localhost por la ip del servidor externo al que quieras conectarte si no está en tu host.

    Desde una aplicación

    Es similar al resto de bases de datos.

    Bun/Node

    Necesitarás su driver:

    #bun
bun add redis
#nodejs
pnpm install redis

    import { createClient } from "redis";

const client = createClient({
  url: "redis://myuser:password@localhost:6379",
});

client.on("error", (err) => console.error("Redis Client Error", err));

await client.connect();

await client.set("nombre", "diego");
const value = await client.get("nombre");
console.log("nombre =", value);

await client.disconnect();

    Python

    Muy similar:

    uv init
uv add redis
# lanzar
uv run main.py

    Tu main.py:

    import redis

r = redis.Redis(
    host="localhost",
    port=6379,
    username="myuser",
    password="password",
    decode_responses=True,
)

r.set("nombre", "diego")
value = r.get("nombre")
print(f"nombre = {value}")

    Interactuando con Redis

    Es una base de datos muy simple de entender:

    clave-valor

    Podemos escribir y leer datos simples:

    localhost:6379> set nombre diego
OK
localhost:6379> get nombre
"diego"
localhost:6379> set nombre elvira
OK
localhost:6379> get nombre
"elvira"

    Contadores

    Puedes crear contadores y usar INCR y DECR para modificar su valor:

    localhost:6379> set puntos 0
OK
localhost:6379> INCR puntos
(integer) 1
localhost:6379> INCR puntos
(integer) 2
localhost:6379> INCR puntos
(integer) 3
localhost:6379> get puntos
"3"
localhost:6379> DECR puntos
(integer) 2
localhost:6379> get puntos
"2"

    Listas

    localhost:6379> LPUSH tareas "sacar la basura"
(integer) 1
localhost:6379> LPUSH tareas "leer un rato"
(integer) 2
localhost:6379> LPUSH tareas "hacer la compra"
(integer) 3
localhost:6379> LRANGE tareas 0 -1
1) "hacer la compra"
2) "leer un rato"
3) "sacar la basura"
localhost:6379> LRANGE tareas 0 1
1) "hacer la compra"
2) "leer un rato"

    Usa LPOP para sacar el primer elemento:

    localhost:6379> LPOP tareas
"hacer la compra"
localhost:6379> LRANGE tareas 0 -1
1) "leer un rato"
2) "sacar la basura"

    O RPOP para sacar el último:

    localhost:6379> RPOP tareas
"sacar la basura"
localhost:6379> LRANGE tareas 0 -1
1) "leer un rato"

    Sets

    Como las listas, pero no puede haber elementos duplicados:

    localhost:6379> SADD colores rojo
(integer) 1
localhost:6379> SADD colores verde
(integer) 1
localhost:6379> SADD colores azul
(integer) 1
localhost:6379> SADD colores rojo
(integer) 0
localhost:6379> SMEMBERS colores
1) "rojo"
2) "verde"
3) "azul"

    Tambien podemos comprobar si un valor pertenece a un set:

    localhost:6379> SISMEMBER colores "morado"
(integer) 0
localhost:6379> SISMEMBER colores "rojo"
(integer) 1

    Hash

    Similar a un objeto con multiples clave-valor:

    localhost:6379> HSET usuario:1 nombre "Ana" edad 30 email "ana@gmail.com"
(integer) 3
localhost:6379> HSET usuario:2 nombre "Diego" edad 23 email "diego@gmail.com"
(integer) 3
localhost:6379> HGETALL usuario:1
1) "nombre"
2) "Ana"
3) "edad"
4) "30"
5) "email"
6) "ana@gmail.com"
localhost:6379> HGET usuario:1 email
"ana@gmail.com"
localhost:6379> HGET usuario:2 email
"diego@gmail.com"

    Redis tiene más tipos, dependiendo de qué necesites, estos son los más básicos y que más usarás, consulta la documentación antes de implementar cualquier solución, puedes encontrar algun tipo que quizá encaje mejor.
