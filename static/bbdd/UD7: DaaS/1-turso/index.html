    Turso

    Turso es un servicio de base de datos en la nube, te permite crear bases de datos SQL en la nube sin tener que preocuparte por la infraestructura de servidor.

    Turso está basado en LibSQL, un fork del conocido SQLite, lo que significa que puedes usar SQLite para empezar el desarrollo localmente y luego desplegarlo en Turso, facilitando la migración de tu aplicación a la nube.

    Aunque puedes usar la documentación oficial para empezar a usar Turso, aquí tienes una guía rápida para comenzar.

    Deuda técnica

    Una de las ventajas de turso es que genera relativamente poca dependencia del proveedor (vendor lock-in). Al estar usando SQLite, si en algún momento quieres dejar de usar turso, migrar los datos y continuar gestionandolo por tu cuenta se hace con pocos cambios en el código.

    Sin embargo, Turso sí aporta funcionalidades que no obtendrías simplemente utilizando SQLite, especialmente su sistema de réplicas y distribución geográfica. Si tu aplicación depende de estas características, dejar Turso puede ser más costoso: tendrías que implementar y mantener por tu cuenta mecanismos de replicación, sincronización y distribución.

    Instalación

    Crea una cuenta e inicia sesión en Turso.

    Lanza el siguiente comando para instalar la herramienta de línea de comandos de Turso:

    curl -sSfL https://get.tur.so/install.sh | bash

    Prueba a lanzar turso en la terminal para ver si se instaló correctamente y los comandos disponibles:

    ❯ turso

    Si tienes algun error al ejecutar turso, asegúrate de añadir el PATH a tu .bashrc. Abre el archivo ~/.bashrc y añade la siguiente línea al final del archivo:

    export PATH="/home/datadiego/.turso:$PATH"

    Cuando se termina de instalar la aplicación, te darán la ruta que debes añadir al $PATH

    Asegúrate de usar tu ruta de instalación de Turso, que puede ser diferente a la mía.

    Iniciar sesión

    Vamos a iniciar sesión en Turso desde la línea de comandos. Ejecuta el siguiente comando:

    turso auth login

    Se abrirá una ventana del navegador donde podrás iniciar sesión en tu cuenta de Turso. Una vez que hayas iniciado sesión, vuelve a la terminal y verás un mensaje de éxito:

    Crear la base de datos

    Usamos el comando turso db create <nombre> para crear una nueva base de datos:

    turso db create testing

    Nos da tres opciones para interactuar con la base de datos:

    • Abrir una consola SQL interactiva con turso db shell <nombre>. Esto nos permite ejecutar consultas SQL directamente en la base de datos.
    • Ver información sobre la base de datos con turso db show <nombre>. Esto nos da información sobre la base de datos, incluyendo la URL de conexión.
    • Crear un token de autenticación con turso db tokens create <nombre>. Esto es necesario para conectarnos a la base de datos desde nuestra aplicación, pero para interactuar directamente desde la línea de comandos no es necesario.

    Información de la base de datos

    Si lanzas db show <nombre> verás algo similar a esto:

    Algunos campos importantes a tener en cuenta:

    • Name: Nombre de la base de datos.
    • URL: URL de conexión a la base de datos. Esta es la URL que usaremos para conectarnos a la base de datos desde nuestra aplicación.
    • ID: ID de la base de datos.
    • Group: Grupo al que pertenece la base de datos. Los grupos son una forma de organizar tus bases de datos en Turso.
    • Locations: Ubicación de la base de datos. Esto es importante para la latencia y el rendimiento de la base de datos.

    Crear una tabla

    Iniciamos una shell de SQL con turso db shell <nombre>:

    ❯ turso db shell testing
Connected to testing at libsql://testing-datadiego.aws-eu-west-1.turso.io

Welcome to Turso SQL shell!

Type ".quit" to exit the shell and ".help" to list all available commands.

→

    Y mandamos nuestra primera query de SQL:

    CREATE TABLE users (
  ID INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,
  points INTEGER DEFAULT 0
);

    Ahora podemos ver la tabla creada con el comando .tables:

    datadiego@~ turso db shell datatest
Connected to datatest at libsql://datatest-datadiego.aws-eu-west-1.turso.io

Welcome to Turso SQL shell!

Type ".quit" to exit the shell and ".help" to list all available commands.

→  CREATE TABLE users (
...   ID INTEGER PRIMARY KEY AUTOINCREMENT,
...   name TEXT NOT NULL,
...   points INTEGER DEFAULT 0
... );
→  .tables
users

    Si introducimos .schema veremos la definición de la tabla:

    →  .schema
CREATE TABLE users (                      
ID INTEGER PRIMARY KEY AUTOINCREMENT,     
name TEXT NOT NULL,                       
points INTEGER DEFAULT 0                  
);

    Podemos insertar datos en la tabla con el comando INSERT:

    INSERT INTO users (name, points) VALUES ('test1', NULL);
INSERT INTO users (name, points) VALUES ('test2', 10);

    Y consultar los datos con SELECT:

    →  select * from users;
ID     NAME      POINTS 
1      test2     10         
2      test1     NULL

    Salir de la shell

    Para salir de la shell de SQL, simplemente escribe .quit y presiona Enter:

    →  .quit
datadiego@~

    Conectar Turso a tu aplicación

    Para conectarte a Turso desde tu aplicación, necesitas dos elementos:

    Token de autenticación

    Token de autenticación, piensa en el token como en una combinación de usuario+contraseña que te permite acceder a la base de datos.

    Puedes crear múltiples tokens, destinados a diferentes propósitos, por ejemplo:

    • Desarrollador: Este token solo lo tiene el desarrollador de la app.
    • Colaborador: Este token solo lo tiene un colaborador en el proyecto.
    • Aplicación: Este token es el que la app usa para acceder a turso.

    Este token no debe ser expuesto nunca en tu aplicación, o todo el mundo obtendría acceso a modificar y eliminar datos de la misma libremente. Ten en cuenta que usas SQLite de fondo, no hay permisos de usuario, si tienes el token, puedes extraer toda la información de la base de datos, luego hacer DROP a todas las tablas y dejar la aplicación completamente comprometida.

    Para crear el token:

    turso db tokens create <nombre>

    Sustituye <nombre> por el nombre de tu base de datos.

    URL de conexión

    Para poder conectar necesitas también la URL de conexión, puedes verla con turso db show --url <nombre>:

    ❯ turso db show --url testing
libsql://testing-datadiego.aws-eu-west-1.turso.io

    Archivo .env

    Teniendo estos dos datos localizados, podemos empezar a crear nuestro proyecto usando turso, crea un directorio para el mismo y crea un archivo .env dentro del proyecto, rellenando con los valores que ya obtuviste previamente:

    TURSO_DATABASE_URL=""
TURSO_AUTH_TOKEN=""

    Asegúrate de no subir este archivo a tu repositorio ni de compartir el token con nadie. Usa tu archivo .gitignore para que nunca se suba al realizar un commit.

    Conexión con Python

    Teniendo nuestro .env listo, vamos a usar Python para conectarnos.

    Iniciamos un entorno virtual con uv o pip:

    test on  master [?] via 🐍 v3.14.7
❯ uv init
Initialized project `test`

    Y descargamos las dependencias necesarias, libsql-experimental para conectar con turso, y dotenv para acceder a nuestros secretos en el .env:

    ❯ uv add libsql-experimental dotenv
Resolved 4 packages in 4ms
      Built test @ file:///tmp/test                               Prepared 1 package in 3ms
Uninstalled 1 package in 0.15ms
Installed 1 package in 1ms
 ~ test==0.1.0 (from file:///tmp/test)
test on  master [?] is 📦 v0.1.0 via 🐍 v3.14.7

    Crea main.py y añade el siguiente código:

    import libsql_experimental as libsql
import os
import dotenv
dotenv.load_dotenv()
url = os.getenv("TURSO_DATABASE_URL")
auth_token = os.getenv("TURSO_AUTH_TOKEN")

conn = libsql.connect("hello.db", sync_url=url, auth_token=auth_token)
conn.sync()
#select all from users;
users = conn.execute("select * from users").fetchall()
print(users)

    Ejecuta el script y verás los datos de la tabla users:

    ❯ uv run main.py
[(1, 'test1', None), (2, 'test2', 10)]

    Este script usa lo que en turso se conoce como una réplica local, si miras los archivos de tu proyecto:

    Si no hay un SDK disponible de forma oficial o de la comunidad, puedes interactuar con HTTP.

    Conexión con Bun

    En bun es aún más simple, solo necesitas la libreria @libsql/client, crear tu .env y conectar asi:

    import { createClient } from "@libsql/client";

const db = createClient({
  url: Bun.env.TURSO_DATABASE_URL,
  authToken: Bun.env.TURSO_AUTH_TOKEN,
});

const users = await db.execute("select * from users");
console.log(users.rows);
await db.close();

    Revocar tokens

    Puedes eliminar los tokens de autenticación de la base de datos con turso group tokens invalidate <nombre>:

    ❯ turso group tokens invalidate testing
To invalidate tokens for group testing, tokens from all its databases will be invalidated.
All your active connections to the databases in that group will be dropped and there will be a short downtime.

Are you sure you want to do this? [y/n]: y
✔  Success! Tokens invalidated successfully.

    Si uno de los tokens ha sido comprometido, borra los tokens, crea de nuevo todos, envíalos a quienes los necesiten y actualiza tu .env.

    Destruir una base de datos

    Si ya no necesitas la base de datos, puedes eliminarla con turso db destroy <nombre>:

    ❯ turso db destroy testing
Database testing and all its data will be destroyed.
Are you sure you want to do this? [y/n]: y
Destroyed database testing in 606ms.
