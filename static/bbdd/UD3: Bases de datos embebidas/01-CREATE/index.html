    CREATE

    En SQL las sentencias CREATE se usan para crear tablas. Con estas expresiones definimos las columnas que tendrá, que tipo de datos hay en cada una, y comportamientos adicionales que nos pueden interesar para modelar nuestras entidades.

    CREATE es la sentencia que mas cambia entre diferentes motores de bases de datos, cada una ofrece una filosofía diferente a la hora de tipar datos y pueden tener características únicas que en otras no se pueden replicar.

    El resto del lenguaje SQL es bastante estándar entre motores. No cambiará prácticamente.

    Tipado dinámico

    SQLite tiene un sistema de tipos de datos dinámico, lo que significa que no es necesario declarar un tipo de dato específico para una columna.

    Esto puede ser beneficioso cuando queremos crear una base de datos rápidamente, o si una columna puede contener diferentes tipos de datos y no queremos tener que convertirlos por parte de la aplicación cuando llegan a la base de datos.

    CREATE TABLE ejemplo (
    c1,
    c2,
    c3
);

INSERT INTO ejemplo VALUES (123, 'texto', 45.67);
INSERT INTO ejemplo VALUES ('hola', 4.56, 123);

    Esto funciona perfectamente, SQLite no dará error de ningún tipo.

    Incluso cuando indicas el tipo de dato:

    CREATE TABLE ejemplo (
    c1 INTEGER,
    c2 TEXT,
    c3 REAL
);

INSERT INTO ejemplo VALUES (123, 'texto', 45.67);
INSERT INTO ejemplo VALUES ('hola', 4.56, 123);

    No dará error si pasamos un dato que no sea de ese tipo. SQLite intentará convertirlo al tipo de dato adecuado según el contexto.

    Modo estricto

    Si quieres una estructura más solida en tus tablas, puedes usar el modo estricto:

    CREATE TABLE ejemplo (
    c1 INTEGER,
    c2 TEXT,
    c3 REAL
)STRICT;

INSERT INTO ejemplo VALUES (123, 'texto', 45.67);
INSERT INTO ejemplo VALUES ('hola', 4.56, 123);

    Ejecutar esto si dará error:

    ❯ sqlite3 test.db < schema.sql 
Runtime error near line 8: cannot store TEXT value in INTEGER column ejemplo.c1 (19)

    Datatypes

    Los tipos de datos principales en SQLite son:

    • INTEGER: Un número entero. Puede ser de 1, 2, 3, 4, 6, 8 bytes dependiendo del valor.
    • REAL Un número de punto flotante de 8 bytes.
    • TEXT: Una cadena de texto. Puede ser de cualquier longitud.
    • BLOB: Un objeto binario grande. Se utiliza para almacenar datos binarios como imágenes o archivos.
    • DATATIME: Datos temporales como fechas y horas.
    • NULL: Un valor nulo.

    Modificadores

    Además del tipo de dato, podemos añadir varios modificadores a las columnas:

    • PRIMARY KEY: Define una columna como clave primaria.
    • FOREIGN KEY: Define una columna como clave foranea.
    • AUTOINCREMENT: Hace que la columna se incremente automáticamente con cada inserción.
    • NOT NULL: Asegura que la columna no puede contener valores nulos.
    • UNIQUE: Asegura que los valores en la columna son únicos.
    • DEFAULT: Define un valor por defecto para la columna si no se especifica uno al insertar.
    • CHECK: Añade lógica a comprobar por parte de la columna.

    Un ejemplo donde usamos estos modificadores:

    CREATE TABLE users (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,
  email TEXT NOT NULL UNIQUE,
  age INTEGER NOT NULL,
  bio TEXT DEFAULT '¡Hola!',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  CHECK (age > 18)
);

    El orden es importante, para definir una columna:

    nombre tipo modificadores

    En el caso de usar PRIMARY KEY y AUTOINCREMENT estos deben ir en ese orden o fallará.

    Si añadimos un CHECK, o nuestra clave primaria es compuesta, se ponen al final, cuando hayamos definido la última columna de la tabla.

    IF EXISTS / IF NOT EXISTS

    Si intentamos ejecutar múltiples veces el mismo sql que crea una tabla como las vistas hasta ahora, fallará:

    /tmp/testsqlite 
❯ ls
.rw-r--r--@ 239 datadiego  3 sep 17:25 schema.sql

/tmp/testsqlite 
❯ sqlite3 test.db < schema.sql 

/tmp/testsqlite 
❯ ls
.rw-r--r--@ 239 datadiego  3 sep 17:25 schema.sql
.rw-r--r--@ 16k datadiego  3 sep 17:27 test.db

/tmp/testsqlite 
❯ sqlite3 test.db < schema.sql 
Parse error near line 1: table users already exists

    Cuando lo ejecutamos la primera vez se crea la base de datos, a la segunda, intenta crear una tabla que ya existe previamente, y da error.

    Podemos modificar nuestra tabla de la siguiente forma:

    CREATE TABLE IF NOT EXISTS users (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,
  email TEXT NOT NULL UNIQUE,
  age INTEGER NOT NULL,
  bio TEXT DEFAULT '¡Hola!',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  CHECK (age > 18)
);

    Ahora, solo se ejecuta cuando la tabla no existe, si ya hay una tabla de usuarios creada previamente, no se ejecuta.

    Cuidado! Si estás diseñando una base de datos, creas la db, modificas la tabla y contiene un IF NOT EXISTS, las columnas nuevas o cambios que existan no se aplicarán, tendrás que borrar la tabla con un DROP o borrar la base de datos entera si aun estás en la fase de diseño de la misma.

    .tables

    La orden .tables es exlusiva de SQLite, te devuelve que tablas hay creadas en una base de datos.

    No necesitan tener datos dentro, solo haber sido ejecutados mediante un CREATE:

    /tmp/testsqlite 
❯ sqlite3 test.db < schema.sql 

/tmp/testsqlite 
❯ sqlite3 test.db ".tables"
users

    Semántica

    A la hora de crear tablas, deberías acostumbrarte a seguir ciertas normas a la hora de nombrar las tablas y columnas:

    • Los nombres de las tablas en plural.
    • Los nombres de las columnas en singular.
    • Ambos en minúsculas.

    Separar claramente tablas y columnas por plural tiene sentido semántico.

    • La tabla almacena múltiples filas.
    • Las columnas deben guardar un único valor.
