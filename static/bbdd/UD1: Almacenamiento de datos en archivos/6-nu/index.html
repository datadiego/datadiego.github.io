    Nushell

    Nushell es algo un poco diferente a lo que hemos dado hasta ahora.

    Las herramientas de csvlook, jq o yq son comandos que ejecutan una tarea concreta, pueden usarse con pipes | para encadenar comportamientos.

    Nushell o nu es un shell, cambia por completo el cómo interactuas con tu sistema operativo mediante terminal.

    Que es una shell

    Ahora mismo usas bash como shell en Linux:

    ❯ echo $SHELL
/bin/bash

    Esto te permite escribir comandos en la terminal, la terminal los manda al shell, y esta decide como interpretar lo que escribes para enviar un comando, y luego devolver el resultado.

    La shell más básica que encontrarás es sh, esta tiene un comportamiento muy básico, interpreta el comando, si no es un comando básico a la shell como cd, mkdir o cat, lo busca dentro de los PATH que tienes declarados, y lo ejecuta.

    bash, el que estás usando, expande la shell sh y te permite hacer más cosas, por ejemplo:

    /tmp/test
❯ echo {1..5}
1 2 3 4 5

/tmp/test
❯ mkdir carpeta-{1..5}

/tmp/test
❯ ls
drwxr-xr-x@ - datadiego 15 sep 19:13 carpeta-1
drwxr-xr-x@ - datadiego 15 sep 19:13 carpeta-2
drwxr-xr-x@ - datadiego 15 sep 19:13 carpeta-3
drwxr-xr-x@ - datadiego 15 sep 19:13 carpeta-4
drwxr-xr-x@ - datadiego 15 sep 19:13 carpeta-5

    También añade elementos como los arrays:

    /tmp/test
❯ lista=(uno dos tres)

/tmp/test
❯ echo "${lista[0]}"
uno

/tmp/test
❯ echo "${lista[1]}"
dos

/tmp/test
❯ echo "${lista[2]}"
tres

    Y funciones, que facilitan el scripting y añadir funcionalidades nuevas a tu flujo de trabajo:

    create_test(){
  rm -rf /tmp/test
  mkdir /tmp/test
  cd /tmp/test
  git init
  touch README.md
}

create_test()

    Existen otras shells, como fish o [zsh], que añaden diferentes comportamientos y capacidades, desde sugerencias y autocompletado de comandos, a un lenguaje de scripting más moderno que el que usa bash.

    Filosofia de nu

    Nu no se limita a cambiar el lenguaje de scripting que podemos usar, cambia por completo como se interpretan los datos que devuelve tu terminal cuando lanzas un comando.

    Todos los shells que existían hasta ahora tratan los datos como texto. Tenemos múltiples herramientas que nos dejan manipular y extraer información de texto desde la terminal:

    # extraer procesos llamados nvim
❯ ps aux | grep nvim
datadie+    6561  0.1  0.0 239924 10068 pts/0    S+   20:51   0:00 nvim 6-nu.md
datadie+    6562 14.9  0.1 337836 75380 ?        Ssl  20:51   0:38 nvim --embed 6-nu.md
datadie+    8511  0.0  0.0 231616  2492 pts/1    S+   20:56   0:00 grep --color=auto nvim

# Extraer PIDs de estos procesos
❯ ps aux | grep nvim | awk '{print $2}'
6561
6562
8716

    Operaciones

    nu incluye muchas operaciones para manipular datos, por ejemplo:

    ~> ps | first 3
╭───┬─────┬──────┬────────────────────────┬──────────┬──────┬──────────┬──────────╮
│ # │ pid │ ppid │          name          │  status  │ cpu  │   mem    │ virtual  │
├───┼─────┼──────┼────────────────────────┼──────────┼──────┼──────────┼──────────┤
│ 0 │   1 │    0 │ systemd                │ Sleeping │ 0.00 │ 20.0 MiB │ 38.7 MiB │
│ 1 │   2 │    0 │ kthreadd               │ Sleeping │ 0.00 │      0 B │      0 B │
│ 2 │   3 │    2 │ pool_workqueue_release │ Sleeping │ 0.00 │      0 B │      0 B │
╰───┴─────┴──────┴────────────────────────┴──────────┴──────┴──────────┴──────────╯

    El programa ps muestra todos los procesos del sistema, podemos quedarnos con los tres primeros procesos que se iniciaron con el filtro first 3.

    Ayuda con nu

    nu es una shell muy extensa como para explicar todo aqui, pero incluye un comando help commands que te ayuda a encontrar que comandos tiene tu shell nueva, por ejemplo:

    # todos los comandos
help commands
# todos los comandos en la categoria de formatos
help commands | where category == formats

    También tienes disponible el comando tutor, que te guiará con un tutorial acerca de los aspectos fundamentales de la shell.

    Manipulando datos

    El aspecto que más va a cambiar tu forma de aproximarte a los archivos con datos es que nu los convierte todos en textos estructurados. Y te da una interfaz uniforme sobre la que trabajar con ellos.

    Considera el siguiente json:

    [
  {
    "nombre": "Diego",
    "edad": 35,
    "email": "diego@gmail.com"
  },
  {
    "nombre": "Pepe",
    "edad": 22,
    "email": "pepe@gmail.com"
  },
  {
    "nombre": "Maria",
    "edad": 26,
    "email": "maria@gmail.com"
  },
  {
    "nombre": "Elvira",
    "edad": 29,
    "email": "elvira@gmail.com"
  }
]

    Con nu podemos hacer:

    /tmp/text-based> cat usuarios.json | from json
╭───┬────────┬──────┬──────────────────╮
│ # │ nombre │ edad │      email       │
├───┼────────┼──────┼──────────────────┤
│ 0 │ Diego  │   35 │ diego@gmail.com  │
│ 1 │ Pepe   │   22 │ pepe@gmail.com   │
│ 2 │ Maria  │   26 │ maria@gmail.com  │
│ 3 │ Elvira │   29 │ elvira@gmail.com │
╰───┴────────┴──────┴──────────────────╯
/tmp/text-based> cat usuarios.json | from json | where edad > 30
╭───┬────────┬──────┬─────────────────╮
│ # │ nombre │ edad │      email      │
├───┼────────┼──────┼─────────────────┤
│ 0 │ Diego  │   35 │ diego@gmail.com │
╰───┴────────┴──────┴─────────────────╯

    No solo eso, podemos convertir a csv:

    /tmp/text-based> cat usuarios.json | from json | to csv
nombre,edad,email
Diego,35,diego@gmail.com
Pepe,22,pepe@gmail.com
Maria,26,maria@gmail.com
Elvira,29,elvira@gmail.com

    Extendiendo nu

    nu no puede llegar a todos los comandos, existen demasiados paquetes que devuelven su contenido en texto y nu no puede convertirlos tan fácilmente en datos estructurados, un buen ejemplo es ss, usado para ver información sobre las conexiones de red y puertos de nuestro sistema:

    ❯ ss -putan | head -n 3
