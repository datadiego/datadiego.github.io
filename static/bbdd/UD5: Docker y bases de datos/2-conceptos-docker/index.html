    Conceptos básicos de Docker

    Vamos a repasar rápidamente los conceptos básicos que necesitas comprender cuando usas docker:

    Docker

    Docker empaqueta y ejecuta aplicaciones de forma aislada. La aplicación funciona igual, ya sea en tu ordenador, en el de un compañero con otro sistema operativo, o un servidor.

    Imagen

    Es una plantilla inmutable, siempre que se crea un contenedor a partir de una imagen se obtiene la misma aplicación y entorno.

    Piensa en una imagen como en la .iso que descargas para instalar una distro, una vez lo instalas, obtienes un sistema operativo, con la imagen obtienes una distro minima, con un sistema de archivos, usuarios, permisos y gestor de paquetes. En una versión mínima que permite descargar las dependencias que tu aplicación necesite para funcionar y arrancar.

    Contenedor

    Un contenedor es una instancia de una imagen ejecutandose, puedes tener múltiples contenedores creados a partir de una imagen.

    Dockerfile

    Un Dockerfile es un archivo que contiene las instrucciones para construir una imagen.

    Por ejemplo:

    FROM ubuntu

RUN apt update
RUN apt install figlet

COPY . .

CMD ["figlet", "-f", "slant", "docker"]

    Este Dockerfile creará una imagen a partir de la imagen de ubuntu que vimos antes. Actualizará el gestor de paquetes, instalará una dependencia, copiará todo el contenido del directorio en el que tenemos nuestro Dockerfile (incluyendo el Dockerfile), y por ultimo, ejecutará el comando que le pasamo, y por ultimo, ejecutará el comando que le pasamos.

    Redes

    Docker puede lanzar redes para exponer servicios que tengas en tus contenedores a tu sistema o cualquiera con acceso a tu IP.

    Podrás elegir en que puerto quieres bindear el servicio cuando lances el contenedor.

    Volumenes

    Si quieres que el contenedor pueda almacenar y compartir archivos con tu sistema, puedes crear un volumen de memoria para que queden compartidos.

    Compose

    En ocasiones, un contenedor necesita múltiples contenedores orquestados a la vez, por ejemplo, una aplicación web puede necesitar:

    • Express en nodejs o Springboot en Java para el servidor web.
    • mySQL como base de datos que consume el servidor web.
    • nginx como proxy.

    Cada uno puede definirse por separado, y orquestarse desde un archivo docker-compose.yml, por ejemplo:

    services:
  mongo:
    image: mongo
    restart: always
    ports:
      - 27017:27017
    environment:
      MONGO_INITDB_ROOT_USERNAME: admin
      MONGO_INITDB_ROOT_PASSWORD: adminpass

  mongo-express:
    image: mongo-express
    restart: always
    ports:
      - 8081:8081
    environment:
      ME_CONFIG_MONGODB_URL: mongodb://admin:adminpass@mongo:27017/
      ME_CONFIG_BASICAUTH_ENABLED: true
      ME_CONFIG_BASICAUTH_USERNAME: admin
      ME_CONFIG_BASICAUTH_PASSWORD: adminpass

    Este docker-compose.yml lanza dos servicios:

    • mongo: la base de datos mongodb. Funcionando en el puerto 27017.
    • mongo-express: un servidor express que se conecta a la base de datos. Funcionando en el puerto 8081
