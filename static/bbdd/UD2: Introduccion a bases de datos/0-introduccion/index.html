    Conceptos básicos de bases de datos

    Introducción

    Antes de empezar a usar bases de datos, vamos a conocer que tipos podemos encontrar, que clasificaciones existen, y conocer cuando una nos puede interesar más que otra.

    Entender esta clasificación es muy importante a la hora de comenzar un proyecto. Elegir mal el tipo de base de datos que vamos a utilizar conlleva una deuda tecnológica muy elevada.

    También veremos algunos conceptos compartidos a lo largo de la mayoría de bases de datos cuando interactuamos con ellas.

    ¿Cómo sé que base de datos es mas conveniente?

    No lo sabrás hasta que realmente uses varias en producción :)

    Pero hay una serie de preguntas que deberíamos hacernos antes de elegir la que más nos gusta o conocemos sin pensar realmente en si es la mejor opción:

    • ¿Que tipo de aplicación es? Si es de escritorio o movil, seguramente una embebida sea la mejor opción.
    • ¿Va a ser consumida por múltiples usuarios? ¿Cuantos? Podemos alargar mucho una embebida, pero una aplicación gigantesca quizá necesite una de servidor.
    • ¿Nos compensa poder configurar permisos de acceso? Si separar que pueden acceder unos usuarios de otros es importante, la base de datos debe permitirlo.
    • ¿Como de extensible debe ser? Postgresql es famosa por los plugins que nos ayudan a manejar datos, pero si nadie en el equipo lo conoce y no vamos a sacarle partido, no tiene sentido elegirla.
    • ¿Los datos cambian muy rápido? Si necesitas métricas en tiempo real, una base de datos como Redis es perfecta, pero SQLite se ahogará.
    • ¿La estructura de datos está definida o puede variar? Postgresql nos permite ser mas flexibles, o quizá podemos usar directamente una opción nosql donde no tenemos estructura definida.
    • ¿Que presupuesto tenemos? Elegir un gestor de código abierto es gratis, pero si podemos pagar por un servicio, quizá podemos tener una solución más rápida de implementar.
    • ¿Queremos controlar nosotros la infraestructura? Si es asi, necesitaremos algo de código abierto o con una versión community que podamos instalar en un servidor.

    Modelos

    Para comparar los tipos de bases de datos utilizaremos diferentes marcos, que las agrupan segun diferentes criterios, estos marcos no son excluyentes, cada uno trata una dimensión diferente, una base de datos ocupa una posición en cada una de estos criterios:

    Según el despliegue

    Si vamos a desplegarlo en un servidor o está embebida en el propio dispositivo.

    Según su arquitectura

    Pueden ser centralizadas si solo está en un dispositivo, o distribuida si hay réplicas de la misma en múltiples ubicaciones geográficas.

    Según lenguaje e interfaz

    Pueden darnos un lenguaje estandar como SQL, o tener su propia libreria para interactuar con la misma.
