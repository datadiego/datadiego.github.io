    Tipos

    Una de las cosas que nos permite Typescript es tipar cualquier dato en nuestro código.

    Recuerda que los docs oficiales tienen una guia mucho mas completa, y muy bien documentada.

    Primitivos

    Podemos tipas string, number y boolean:

    const nombre: string = "javier"
const edad: number = 35
const registrado: boolean = true

    Los tipos se añaden a la derecha de la declaración del nombre de la variable.

    Inferencia de tipos

    Cuando puede, typescript infiere el tipo de una variable según contexto:

    //ts infiere que str es un string
let str = "hola mundo"

//ts infiere que el resultado de what es o un string, o un numero, o un booleano
let what = () =>{
  let mix = ["string", 123, true, false]
  return mix[Math.floor(Math.random() * mix.length)]
}

//ts es incapaz de inferir que va a devolver una API, data es de tipo any
fetch("someapy.com/users")
.then(response => response.json())
.then(data => console.log(data))

    any

    El tipo any, puede ser cualquier cosa, typescript no arrojará ningún error de tipo con estos datos.

    let what: any = ":)"
what * 2

    Si su tipo fuera string, mostraría el fallo.

    Cuando typescript no puede inferir el tipo por contexto, por defecto usará any.

    Arrays

    También podemos tipar arrays especificando que tipo de datos hay dentro:

    const numeros: number[] = [1, 2, 3, 4]
let strings1: string[] = ["a", "b", "c", "d"]
let strings2: string[] = "abcde".split("")
let booleans: boolean[] = [true, false, false, true]
let varios: any[] = [1, "2", true]

    Cuando usas any, cualquier tipo es válido dentro del mismo

    Tipos en funciones

    Podemos tipar tanto los argumentos como el resultado de una función:

    const saludo = (nombre: string) : string => `hola ${nombre}`

    Aquí, la función saludo espera un argumento de tipo string, y devuelve un string.

    En este caso, realmente podríamos hacer:

    const saludo = (nombre: string) => `hola ${nombre}`

    Typescript es capaz de inferir que el resultado es un string por contexto.

    En esta:

    let what = () => {
  let mix = ["string", 123, true, false]
  return mix[Math.floor(Math.random() * mix.length)]
}

    Typescript infiere que what devuelve string|number|boolean, uno de esos tres tipos.

    También puedes tipar una función que devuelve una promesa:

    async function what(): Promise<number> {
  return 123
}

what().then(data => console.log(data+1))

    Tipos en funciones anónimas

    Typescript puede inferir el tipo de la variable que se pasa en una función anónima:

    const frutas = ["manzana", "mango", "melocoton"]

frutas.forEach(fruta => {
  console.log(fruta)
})

    Aquí es capaz de inferir que fruta es un string, tu IDE debería mostrarlo.

    Si la función espera un objeto como argumento, puedes tipar cada una de las claves:

    function registrar(user: { nombre: string; edad: number }) {
  if(user.edad >= 18){
    console.log(`Hola ${user.nombre}`)
  } else {
    console.log("No puedes registrarte si eres menor de edad")
  }
}

    Y si alguna clave puede ser opcional, añades ?:

    const showProfile = (user: {nombre: string, bio?: string}) => {
  console.log(`Hola ${user.nombre}`)
  if(user.bio){
    console.log(user.bio)
  }
}

showProfile({nombre: "Diego"})
showProfile({nombre: "Javier", bio: "Me llamo javier, soy de Malaga!"})

    Union

    Podemos especificar varios tipos en una variable o argumento de funcion:

    let edad: number|string = "diecinueve"
edad = 19
edad = "19"

    También podemos usarlo para especificar ciertos valores concretos:

    let dificultad : "facil"|"medio"|"dificil" = "facil"
dificultad = "heroica"

    dificultad = "heroica" da error, pero "facil", "medio" o "dificil" son válidos.

    Alias

    Puedes crear tus propios tipos, es más fácil usarlos en nuestro código:

    type User = {
  name: string;
  age?: number;
  email: string;
  type: "admin" | "user" | "guest";
}

const usuario0: User = {
  name: "javier",
  age: 32,
  email: "javier@gmail.com",
  type: "admin"
}

const saludo = (user: User) => console.log(`Hola ${user.name}`)

    También puedes usarlos junto a uniones:

    type User = {
  name: string;
  age?: number;
  email: string;
  type: UserType;
}

type UserType = "admin" | "user" | "guest"

    Interfaz

    Una interfaz es muy similar a un alias, nos permiten definir un tipo personalizado, con la diferencia que se pueden extender:

    interface Coordinates {
  x: number;
  y: number;
}

interface Sprite extends Coordinates {
  sprite: string;
}

const playerSprite: Sprite = {
  x: 0,
  y: 0,
  sprite: "hero.png"
}

    Y se les pueden añadir nuevas propiedades fuera de su primera declaración:

    interface User {
  name: string
}

interface User {
  age: number
}

const user: User = {
  name: "javier",
  age: 32
}

    También tienen algunas limitaciones y no pueden representar cosas que type si, por ejemplo, no pueden ser uniones, primitivos o tuplas:

    interface User {
  name: string
}

interface UserType = "user" | "admin" | "guest" //error
interface Coordinates = [number, number] //error

    Lo cierto es que también podemos añadir propiedades nuevas a tipos, y que ambos son bastante intercambiables

    Typescript te avisará si necesitas alguna característica de uno u otro en muchos casos

    La documentación oficial sugiere que uses interface por defecto, y type cuando sea necesario.

    Aserciones

    Los Type Assertions o como suelo llamarlas trust me bro, las usamos en ocasiones en las que typescript no puede tener seguro el tipo de un dato, pero nosotros si, por ejemplo:

    type User = {
  name: string;
  age: number;
}

const response = await fetch("/api/users")
const users: User[] = await response.json()

    Typescript desconoce que devuelve la api, en ese caso, debemos decirle confia en mi, ese endpoint devuelve un array de usuarios:

    const users = await response.json() as User[]

    Otro ejemplo es con bases de datos:

    import { Database } from "bun:sqlite"

type User = {
  name: string;
  age: number;
}

const db = new Database(":memory:")

db.run(`
CREATE TABLE users (
  name TEXT NOT NULL,
  age INT NOT NULL
);
`)

const usuario0 = {
  name: "javier",
  age: 23
}

db.run("INSERT INTO users (name, age) VALUES (?, ?);", [usuario0.name, usuario0.age])

const users: User[] = db.query("SELECT * FROM users").all()

    Typescript no sabe que estructura sigue nuestra tabla users, esto no se puede asegurar:

    const users: User[] = db.query("SELECT * FROM users").all()

    Pero nosotros sabemos que nuestra base de datos devolverá eso, así que podemos decirle a typescript confia en mi, es un array de usuarios:

    const users = db.query("SELECT * FROM users").all() as User[]
