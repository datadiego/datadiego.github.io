    Clientes HTTP

    Un cliente es quien realiza peticiones a un servidor.

    En nuestro caso en esta materia, el cliente más común es un navegador web, pero debemos aprender a utilizar otros si realmente queremos tener más versatilidad a la hora de interactuar con servidores HTTP.

    Utilizaremos dummyjson.com para llamar a una API externa.

    En la documentación de la página verás sobre todo código para interactuar mediante javascript, pero empezaremos usando otros clientes que te ayudarán mucho cuando tengas que consumir APIs.

    Nos centraremos sobre todo en dos endpoints:

    GET https://dummyjson.com/users/
POST https://dummyjson.com/users/add

    El primero nos deja extraer usuarios, el segundo crearlos.

    La acción de POST solo simula la creación de un usuario, dummyjson no crea el usuario en la base de datos del mismo.

    Clientes CLI

    Funcionan desde la terminal, nos permiten realizar llamadas con una sintaxis bastante amigable (dependiendo de la herramienta) y crear scripts rápidamente para interactuar.

    curl

    Es el cliente estándar que viene en Linux, lo encontrarás en cualquier distro, realizar una petición GET es muy sencillo:

    curl https://dummyjson.com/users

    Esto nos devolverá un JSON minificado, podemos explorarlo más fácilmente pipeandolo con jq:

    # obtener el primer usuario
curl https://dummyjson.com/users | jq .users[0]

# obtener username
curl https://dummyjson.com/users | jq .users[0].username

# obtener claves del objeto usuario
curl https://dummyjson.com/users | jq '.users[0] | keys'

    Realizar una petición POST en curl es algo más verboso:

    curl -X POST 'https://dummyjson.com/users/add' \
  -H 'Content-Type: application/json' \
  -d '{
    "firstName": "Pepe",
    "lastName": "Garcia",
    "age": 25
  }'

    Tenemos que pasar tres flags:

    • -X, el método HTTP, cuando no hacemos GET, hay que indiciarlo expresamente.
    • -H, el header de nuestra petición, le indica al servidor que tipo de dato mandamos, en este caso, mandamos el usuario como un JSON.
    • -d, los datos que enviamos al servidor.

    curl es muy útil, está presente en casi cualquier distribución de linux y cualquiera podrá ejecutar tus scripts con el, pero para un uso diario puede ser bastante tedioso

    httpie

    HTTPie simplifica mucho las peticiones en las necesitamos enviar datos. En fedora lo tienes en el propio gestor de paquetes, en otras distribuciones puede que necesites usar otro de los metodos disponibles.

    Si tienes python, puedes instalarlo con pipx install httpie, esto es universal en cualquier sistema operativo.

    Para hacer una petición GET:

    http https://dummyjson.com/users

    Luego puedes usar pipes con jq igual que con curl para navegarlo.

    Para hacer una petición POST:

    http POST https://dummyjson.com/users/add \
  firstName=Pepe \
  lastName=Garcia \
  age:=25

    En httpie, = se usa para valores de texto, := para valores numéricos.

    Si necesitas enviar valores anidados, como la dirección que nos dejan enviar:

    http POST https://dummyjson.com/users/add \
  firstName=Pepe \
  lastName=Garcia \
  age:=25 \
  address[city]=Granada \
  address[country]=Spain

    nushell

    Ya hemos visto algunos usos de nushell en la asignatura de bases de datos.

    Incluye su propio cliente http, y nos deja tratar la respuesta como datos estructurados, es de lejos la forma más sencilla de interactuar con respuestas json:

    Clientes GUI

    También dispones de clientes con interfaz gráfica.

    No vamos a entrar demasiado en ellos, son bastante intuitivos de usar y comprender. Los más famosos son:

    • Postman
    • Hoppscotch
    • Yaak
    • Bruno

    En algunos equipos puede que tengas que usarlas para compartir las peticiones que creas, o usar las de otros compañeros. Pero presentan algunos problemas que el resto de clientes que hemos estudiado no tienen:

    • Dependes en muchos casos de conexión a estos servicios. Si postman se cae, no podéis trabajar con el
    • Los scripts que hagas con cualquier herramienta de CLI se ejecutan en cualquier sistema de forma más cómoda
    • No podéis usarlos en entornos sin interfaz
    • Carecen de control de versiones, los scripts que hagas con cualquier herramienta de CLI pueden vivir en un repositorio
    • Más lentos de crear a costa de su intuitividad, si sabes usar httpie o nu, tardarás menos en crear la petición
