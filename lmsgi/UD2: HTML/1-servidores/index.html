    Servidores

    Para que nuestro navegador pueda ver una página, necesita llamar a un servidor HTTP que aloja los documentos HTML.

    URLs

    Para acceder a uno de estos servidores necesitamos una URL, por ejemplo:

    http://mipagina.com
http://localhost:8000
https://mipagina.com
https://mipagina.com/about.html

    Cada URL se compone de:

    Protocolo + :// + hostname + puerto + / + endpoint

    El protocolo en estos servidores puede ser:

    • http: Sin cifrar el contenido
    • https: Con cifrado de contenido

    El hostname vendrá de tu proveedor de DNS, y si es un servidor local, será localhost o 127.0.0.1.

    El puerto por defecto para servidores http es el :80, si está funcionando en ese, no tenemos por qué indicarlo, si está en uno diferente, debes ponerlo:

    # esto es lo mismo si el servidor está en el puerto 80
https://mipagina.com
https://mipagina.com:80

    Finalmente, necesitarás indicar a que recurso del servidor estás accediendo.

    Si no lo indicas, buscará el archivo index.html en la raiz del servidor.

    Tipos de servidores http

    Necesitarás saber que tipos de servidores existen, dependiendo de en que fase del desarrollo estés usarás unos u otros.

    Servidores estáticos

    Un servidor estático sirve archivos alojados en el mismo, el cliente solicita el archivo y lo envía, bien sea html, css, js, o una imagen, video o sonido.

    El servidor puede tener los siguientes archivos:

    .
├── index.html
├── about.html
├── main.js
├── media
│   ├── background.png
│   ├── bell.wav
│   ├── coche.jpg
│   └── gatos.jpg
└── style.css

    De forma que podríamos acceder a cualquiera de los archivos mediante su url, por ejemplo:

    http://miweb.com -> index.html
http://miweb.com/about.html -> about.html
http://miweb.com/media/gatos.jpg -> gatos.jpg en el directorio /media

    Algunos ejemplos son nginx, apache, o los servidores de desarrollo que veremos más adelante.

    Backend

    Un backend por otro lado además de servir archivos, nos permite definir nuestras propias rutas que ejecutan lógica, puede ser desde interactuar con una base de datos instalada en el sistema a una herramienta que modifique una imagen que el usuario envía.

    Todo esto se hace creando una API, una interfaz que permite al navegador llamar al servidor para ejecutar diferentes bloques de código que el navegador no puede realizar.

    Algunos ejemplos son Express y Elysia en nodejs, Springboot en Java o Django en python.

    Servidor de desarrollo

    Los servidores de desarrollo se utilizan para poder servir nuestro proyecto con html + css + js en nuestro sistema, sin tener que preparar todo un entorno destinado a esto.

    Se levantan muy rápido, y puedes hacerlo en diferentes directorios para poder manejar diferentes proyectos, pero no debes usarlos cuando despliegues la aplicación y la pones disponible al resto de usuarios.

    Vamos a ver varias opciones para levantar un servidor de desarrollo cuando estamos trabajando:

    python3

    Si tienes python3 instalado, puedes levantar un servidor en el directorio que quieras, solo muevete a donde esté tu proyecto con la terminal y ejecuta python3 -m http.server:

    ~
❯ cd /tmp/test/

test on  master [?] via  v22.23.1
❯ ls
.rw-r--r--@ 0 datadiego 27 sep 20:17 about.html
.rw-r--r--@ 0 datadiego 27 sep 20:16 index.html
.rw-r--r--@ 0 datadiego 27 sep 20:17 main.js
drwxr-xr-x@ - datadiego 27 sep 20:17 media
.rw-r--r--@ 0 datadiego 27 sep 20:17 style.css

test on  master [?] via  v22.23.1
❯ python3 -m http.server
Serving HTTP on 0.0.0.0 port 8000 (http://0.0.0.0:8000/) ...

    Una vez esté funcionando, entra desde el navegador en localhost:8000 y tendrás tu página.

    npm

    Si tienes npm instalado, puedes usar npx serve, de nuevo, muévete al directorio de tu proyecto, y lanza ese comando para levantar un servidor.

    ~
❯ cd /tmp/test/

test on  master [?] via  v22.23.1
❯ ls
.rw-r--r--@ 0 datadiego 27 sep 20:17 about.html
.rw-r--r--@ 0 datadiego 27 sep 20:16 index.html
.rw-r--r--@ 0 datadiego 27 sep 20:17 main.js
drwxr-xr-x@ - datadiego 27 sep 20:17 media
.rw-r--r--@ 0 datadiego 27 sep 20:17 style.css

test on  master [?] via  v22.23.1
❯ npx serve

   ┌────────────────────────────────────────┐
   │                                        │
   │   Serving!                             │
   │                                        │
   │   - Local:    http://localhost:3000    │
   │   - Network:  http://172.18.0.1:3000   │
   │                                        │
   │   Copied local address to clipboard!   │
   │                                        │
   └────────────────────────────────────────┘

    Este se levanta en el puerto 3000, podrás accederlo en el navegador mediante localhost:3000.

    Lo ideal con los servidores de desarrollo es tenerlos en un alias si usas Linux, por ejemplo:

    alias server="python3 -m http.server"
