    Mermaid

    Markdown se puede extender de muchas formas, y añadir elementos que de base no están en su lenguaje. Uno de los más comunes es mermaid.

    Mermaid nos permite crear diagramas de diferentes tipos usando texto, lo interesante de usarlo en markdown es que no tenemos que guardar la imagen y usarlo asi:

    ![mi diagrama](./ruta/al/diagrama.png)

    Esto es incómodo, si cambiamos el diagrama tenemos que volver a guardar la imagen en el directorio.

    Si el programa que usas para parsear y renderizar tu markdown a html es capaz de integrar mermaid, basta con escribirlo en un bloque de código y decirle que el lenguaje que usa es mermaid para que lo renderice directamente:

    stateDiagram-v2
    [*] --> Still
    Still --> [*]
    Still --> Moving
    Moving --> Still
    Moving --> Crash
    Crash --> [*]

    Asi podemos modificar el diagrama directamente en el propio documento, actualizarlo si algo cambia, e incluso el cómo se renderiza sobre la marcha.

    Tiene muchos tipos de diagrama en su motor, puedes verlos todos en la documentacion, cada uno tiene una sintaxis bastante minima.

    Diagramas como texto

    Es posible que de primeras parezca que escribir diagramas en lugar de usar un editor con interfaz como diagrams.net es algo obtuso, pero presenta muchas ventajas:

    Versionado con git

    Al ser texto, se puede versionar con git, revisar cambios y recuperar versiones previas, con un diagrama creado gráficamente esto no es posible.

    Reproducibilidad

    Tus diagramas comparten un mismo estilo y homogeneidad entre ellos, en un equipo donde múltiples personas están creando diagramas colocando cajas manualmente este problema crece con facilidad.

    Facilita la documentación técnica

    El diagrama vive en el propio texto, encaja directamente con markdown, github, gitlab y wikis.

    Rapidez de edición

    La facilidad que te da un editor gráfico inicialmente se pierde rápidamente cuando tenemos múltiples elementos situados y nos piden hacer un cambio que afecta a varios, tendremos que empezar a moverlos todos y hacer hueco para el nuevo elemento, en mermaid se calcula automáticamente y posiblemente con escribir un par de lineas de texto lo tenemos hecho.

    Te obliga a pensar en estructura

    Esto hace que te centres en lo que verdaderamente importa, que tiene que representar tu diagrama, no en donde poner cajas, hacer click en nodos y dibujar flechas.

    Automatización

    Al ser texto, puedes generar diagramas a partir de datos mediante código. Incluirlo en pipelines, documentación automática, testing, etc.

    Tipos de diagramas

    Mermaid posee demasiados tipos de diagramas para comentarlos todos, pero vamos a comentar los que más útilidad te darán durante el curso:

    Diagramas de flujo

    Representa un proceso o algoritmo, muestra que pasos se realizan para solucionar un problema, por ejemplo, este script de python comprueba si un numero es positivo o negativo:

    numero = int(input("Introduce un número: "))

if numero >= 0:
    print("El número es positivo")
else:
    print("El número es negativo")

    Su diagrama de flujo es:

    flowchart LR
    A([Inicio]) --> B[Introducir numero]
    B --> C{Numero >= 0}
    C -->|Si| D[Mostrar positivo]
    C -->|No| E[Mostrar negativo]
    D --> F([Fin])
    E --> F

    Y en mermaid se crea asi:

    flowchart LR
    A([Inicio]) --> B[Introducir numero]
    B --> C{Numero >= 0}
    C -->|Si| D[Mostrar positivo]
    C -->|No| E[Mostrar negativo]
    D --> F([Fin])
    E --> F

    No tienes por qué usar A, B, C para identificar los nodos, si es un diagrama pequeño como este puede valer, pero si es grande se nos terminarán las letras y además cuesta leerlo:

    flowchart LR
    inicio([Inicio]) --> entrada[Introducir numero]
    entrada --> decision{Numero >= 0}
    decision -->|Si| positivo[Mostrar positivo]
    decision -->|No| negativo[Mostrar negativo]
    positivo --> fin([Fin])
    negativo --> fin

    Imagina que realizas este diagrama en un editor gráfico y de pronto te piden que en lugar de ir en horizontal, los nodos vayan en vertical, ¿cuanto tardarías en mover todo? con mermaid basta con cambiar LR (left-right) por TD (top-down).

    Diagramas de clase

    Nos permite crear entidades con propiedades y metodos, si estos son privados o publicos, si la clase hereda de otra y las relaciones con otras clases.

    classDiagram
    direction LR

    Usuario <|-- Administrador
    Usuario -- MessageBoard : interactúa

    class Usuario {
        +int id
        +String nombre
        +String email
        -String password

        +registrarse()
        +iniciarSesion()
        +publicarMensaje()
        +eliminarMensaje()
    }

    class Administrador {
        +String permisos

        +eliminarUsuario()
        +bloquearUsuario()
        +moderarMensajes()
    }

    class MessageBoard {
        +int id
        +String nombre
        +String descripcion
        +String fechaCreacion
        +int numeroMensajes

        +publicarMensaje()
        +mostrarMensajes()
        +eliminarMensaje()
        +editarMensaje()
    }

    Diagramas de entidad-relación

    Representan relaciones entre tablas de una base de datos:

    erDiagram

    CLIENTE ||--o{ MASCOTA : tiene
    MASCOTA ||--o{ CITA : tiene
    VETERINARIO ||--o{ CITA : atiende
    CITA ||--o| CONSULTA : genera
    CONSULTA ||--o{ TRATAMIENTO : incluye
    MEDICAMENTO ||--o{ TRATAMIENTO : utiliza
    CONSULTA ||--o| FACTURA : genera

    CLIENTE {
        int id_cliente PK
        string nombre
        string apellidos
        string telefono
        string email
        string direccion
    }

    MASCOTA {
        int id_mascota PK
        int id_cliente FK
        string nombre
        string especie
        string raza
        string sexo
        date fecha_nacimiento
        float peso
    }

    VETERINARIO {
        int id_veterinario PK
        string nombre
        string apellidos
        string especialidad
        string telefono
        string email
    }

    CITA {
        int id_cita PK
        int id_mascota FK
        int id_veterinario FK
        date fecha
        string hora
        string motivo
        string estado
    }

    CONSULTA {
        int id_consulta PK
        int id_cita FK
        date fecha
        string diagnostico
        string observaciones
    }

    TRATAMIENTO {
        int id_tratamiento PK
        int id_consulta FK
        int id_medicamento FK
        string dosis
        string frecuencia
        int duracion_dias
    }

    MEDICAMENTO {
        int id_medicamento PK
        string nombre
        string descripcion
        float precio
        int stock
    }

    FACTURA {
        int id_factura PK
        int id_consulta FK
        date fecha
        float importe
        string metodo_pago
        string estado
    }
