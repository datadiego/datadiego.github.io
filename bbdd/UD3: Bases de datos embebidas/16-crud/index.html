    Modelos CRUD

    Cuando integramos una base de datos con una aplicación, es común que necesitemos crear un modelo que sirva para interactuar con la misma.

    Modelo-Vista-Controlador

    Cuando hablamos de MVC, o Modelo, Vista y Controlador. Nos referimos a un patrón de arquitectura de software, es decir, una forma de ordenar los archivos, funciones y clases de nuestra función, con el fin de simplificar el desarrollo de las mismas.

    • Modelo: La lógica de negocio de nuestra aplicación, son las funciones y clases que el usuario va a ejecutar mediante una interfaz programática.
    • Vista: Lo que el usuario ve y que le sirve para interactuar en última instancia con el modelo.
    • Controlador: El puente entre los dos, recibe la petición u orden del usuario, y ejecuta la función del modelo que necesita.

    Ejemplo en un servidor web

    1. El cliente entra a la página, es presentado con la Vista de un formulario de login.
    2. El cliente rellena el login con sus datos, al hacer click en Enviar, se realiza una petición HTTP POST a la ruta /login al servidor con sus datos.
    3. El controlador recibe la petición, extrae los datos de usuario y ejecuta la funcion auth(db, username, password), esta función extrae los datos de la base de datos, comprueba que las credenciales son correctas y crea una sesión en el servidor. Luego devuelve el token de sesión al controlador.
    4. El controlador devuelve el token de sesión al usuario y redirige a /home al usuario.

    Ejemplo en una aplicación CLI local

    1. El usuario lanza la aplicación, se le presenta una vista con un menú donde puede seleccionar varias opciones.
    2. El usuario selecciona Crear nueva nota.
    3. El controlador recibe Crear nueva nota, y muestra el menú correspondiente donde el usuario puede introducir un titulo y contenido.
    4. El usuario ingresa los datos y pulsa enter en la vista.
    5. El controlador ejecuta la función crear_nota(db, titulo, contenido) del modelo notas.
    6. La función ejecuta un INSERT en la base de datos y devuelve True cuando termina.
    7. El controlador devuelve el mensaje Nota añadida y el menu de inicio al usuario.

    Creando un CRUD

    Vamos a crear una aplicación sencilla de notas con bun y sqlite.

    En un directorio vacío, crea un proyecto de bun lanzando bun init, selecciona el template Blank.

    Nuestro proyecto acabará teniendo esta estructura:

    .
├── bun.lock
├── db
│   ├── app.db
│   ├── init.ts
│   └── schema.sql
├── index.ts
├── models
│   └── notes.ts
├── node_modules
├── package.json
├── tsconfig.json
├── tui.ts
└── types.ts
    • /db: Directorio donde tendremos todo lo relativo a la base de datos.
      • app.db: La base de datos sqlite
      • init.ts: Inicia la base de datos y devuelve un objeto Database para que bun pueda interactuar con la base de datos.
      • schema.sql: Nuestra declaración de tablas.
    • index.ts: El entrypoint de nuestra aplicación, lo que ejecutaremos.
    • models: Directorio para los diferentes modelos que usará nuestra app.
      • notes.ts: Nuestro modelo para la tabla de notas
    • node_modules: Directorio con las dependencias y librerias que usaremos.
    • package.json: Archivo que controla que librerias tenemos instaladas.
    • tsconfig.json: Configuración de typescript.
    • tui.ts: Archivo para la interfaz de terminal que presentamos al usuario.
    • types.ts: Tipos para typescript.

    Inicialización de la base de datos

    Todo lo referente a la base de datos irá en el directorio db del proyecto.

    Empecemos por crear un schema.sql:

    CREATE TABLE IF NOT EXISTS notes (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  title TEXT NOT NULL,
  content TEXT NOT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

    Luego, vamos a crear init.ts para inicializar la base de datos:

    import {Database} from "bun:sqlite"

export const db = new Database("./db/app.db")
db.run("PRAGMA foreign_keys = ON")
const schema = await Bun.file("./db/schema.sql").text()
db.run(schema)

    Exportamos el objeto db para usarlo en el resto del programa.

    Probamos a ejecutar el archivo init.ts para comprobar que todo está bien:

    Creando un modelo

    Antes de crear el modelo en si, vamos a crear un archivo types.ts con un tipo para nuestras notas:

    export type note = {
  id: number
  title: string
  content: string
  created_at: string
}

    Todos los modelos deben ir en el directorio models, solo necesitamos uno por ahora, notes.ts:

    import {Database} from "bun:sqlite"
import type{note} from "../types.ts"

export const readNotes = async(db: Database): Promise<note[]> => {
  const query = "SELECT * FROM notes"
  const notes = db.query(query).all() as note[]
  return notes
}

export const createNote = async(db: Database, title: string, content: string) => {
  const query = db.prepare("INSERT INTO notes (title, content) VALUES (?, ?)")
  query.run(title, content)
}

    Por ahora nos basta con esto, vamos a importar las funciones a index.ts y probarlas:

    import {db} from "./db/init.ts"
import {createNote, readNotes} from "./models/notes.ts"

createNote(db, "probando", "esto es una prueba")
const notas = await readNotes(db)

console.log(notas)

    Probamos si funciona:

  }

    El modelo funciona!

    Deberás crear una función updateNote y otra función deleteNote para completar el modelo CRUD.

    Probando a crear una interfaz TUI

    Ya tenemos dos opciones básicas de nuestro CRUD, podemos crear y leer las notas.

    Vamos a comenzar a crear una interfaz con la que un usuario pueda interactuar con los modelos sin tener que andar ejecutando el funciones.

    Añade la librería @clank/prompts, esto nos permitirá crear una interfaz simple de usuario, para aprender a usarla, crearemos un archivo temporal llamado test.ts:

    import { select, text, confirm } from "@clack/prompts";

const nombre = await text({message: "Introduce tu nombre:"})

const opcion = await select({
message: "¿Que quieres?", 
options: [
    {value: "hola", label: "Dime hola"},
    {value: "adios", label: "Dime adios"},
  ]
})

switch (opcion) {
  case "hola":
    console.log(`Hola ${nombre.toString()}`)
    break;
  case "adios":
    console.log(`Adios ${nombre.toString()}`)
    break;

  default:
    break;
}

    Creando la TUI para nuestra app

    Vamos a crear un archivo tui.ts que tendrá toda la lógica de los menús para nuestra app.

    Empecemos por definir un esqueleto básico:

    import { select, text, confirm } from "@clack/prompts";
import { createNote, readNotes } from "./models/notes";
import {Database} from "bun:sqlite"

export const mainMenu = async(db: Database) => {
  const sel = await select({
    message: "Opciones:",
    options: [
      { value: "createNote", label: "Crear una nota" },
      { value: "readNotes", label: "Leer notas" },
      { value: "exit", label: "Salir" }
    ]}
  )
  switch (sel) {
    case "createNote":
      createNoteOption(db)
      break;

    case "readNotes":
      readNotesOption(db)
        break;

    default:
      break;
  }
}

const createNoteOption = async(db: Database) => {
  console.clear()
  console.log("Preguntar datos y ejecutar modelo")
  mainMenu(db)
}

const readNotesOption = (db: Database) => {
  console.clear()
  console.log("Leer todas las notas")
  mainMenu(db)
}

    Ahora podemos navegar por las opciones que tenemos implementadas, elegir una, y tenemos dos funciones aisladas para cada una de las opciones.

    Vamos a usar nuestros modelos en cada una de las funciones:

    const readNotesOption = async(db: Database) => {
    const notes = await readNotes(db)
      console.clear()
      console.log(notes)
      mainMenu(db)
}

const createNoteOption = async(db: Database) => {
      const title = await text({message: "Titulo:"})
      const content = await text({message: "Contenido:"})
      const ok = await confirm({message:`\nTitulo: ${title.toString()}\nDescripcion: ${content.toString()}\n¿Crear la nota?`}) 
      if(ok){
        console.clear()
        console.log("Nota insertada")
        createNote(db, title.toString(), content.toString())
        mainMenu(db)
      } else{
        console.clear()
        console.log("Nota cancelada")
        mainMenu(db)
      }
}

    Ahora tienes el flujo de crear y leer básico listo, si eliges mostrar las notas las muestra en un array usando el modelo para leer la base de datos, y si eliges crear una nota pregunta los datos necesarios y ejecuta el modelo para insertar la nota.
