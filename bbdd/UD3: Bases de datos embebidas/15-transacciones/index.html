    Transacciones

    Las transacciones aseguran que una acción (o varias) se ejecuten hasta el final, de lo contrario, no se completa.

    Es útil en muchos casos y aseguran que los datos y cambios de nuestra base de datos sean integros.

    Vamos a crear una pequeña aplicación para aprender en que nos benefician las transacciones. Y de paso varias cosas más sobre como trabajar con bases de datos en una aplicación.

    El problema de no usar transacciones

    El escenario clásico para demostrar esto es una aplicación de un banco en el que los usuarios pueden enviarse dinero entre ellos.

    Vamos a partir de este schema.sql:

    CREATE TABLE IF NOT EXISTS cuentas (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  nombre TEXT UNIQUE,
  saldo REAL DEFAULT 0,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

    Vamos a recordar qué necesitamos en python para modificar datos de una tabla, crea un archivo main.py:

    import sqlite3

conn = sqlite3.connect("banco.db")
with open("schema.sql", "r") as f:
    schema = f.read()

conn.executescript(schema)
conn.close()
    1. Creamos una conexion
    2. Ejecutamos nuestro SQL, en este caso, nuestro schema.sql.
    3. Hacer un conn.commit(), en este caso, conn.executescript lo hace de forma implicita, pero si usamos conn.execute() deberemos hacerlo.
    4. Cerrar la conexión si no vamos a usarla para hacer más operaciones.

    Para simplificar nuestro código y no tener que estar haciendo todas estas acciones, podemos crear una función wrapper que haga todo esto por nosotros:

    def ejecutar_sql(query, args):
    conn = sqlite3.connect("banco.db")
    conn.execute(query, args)
    conn.commit()
    conn.close()


ejecutar_sql("INSERT OR IGNORE INTO cuentas (nombre, saldo) VALUES (?, ?)",
         ('Javier', 300))


ejecutar_sql("INSERT OR IGNORE INTO cuentas (nombre, saldo) VALUES (?, ?)",
         ('Maria', 0))

    El siguiente problema es el que nos va a mostrar el comportamiento de las transacciones. Ahora mismo nuestra función hace commit tras cada ejecución, pero ¿que pasa si hay un error entre el primer UPDATE y el segundo?

    La aplicación puede provocar un error por otro usuario realizando alguna acción que dispare un bug justo en ese momento, el servidor que consume la base de datos puede tener una caida, un desarrollador tocando en producción puede provocar un corte pequeño justo en ese momento...

    Vamos a simular que se produce un error forzándolo en nuestra función:

    def send_money(sender, receiver, amount):
    rowcount = ejecutar_sql("UPDATE cuentas SET saldo = saldo - ? WHERE nombre = ? AND saldo >= ?",
                            (amount, sender, amount))
    print(f"Filas afectadas: {rowcount}")
    if rowcount == 0:
        print("No se pudo realizar la transferencia")
        return
    raise Exception("Alguien se tropezó con el cable del server")
    ejecutar_sql("UPDATE cuentas SET saldo = saldo + ? WHERE nombre = ?", 
                 (amount, receiver))

    La solución: Transacciones

    La forma de solucionar esto es usando una transacción. Una transacción agrupa varias operaciones en una sola unidad atómica: o se ejecutan todas, o no se ejecuta ninguna.

    Vamos a modificar nuestra función ejecutar_sql() para que pueda trabajar con transacciones:

    def ejecutar_sql(query, args, conn=None):
    if conn is None:
        conn = sqlite3.connect("banco.db")
        cursor = conn.execute(query, args)
        conn.commit()
        conn.close()
    else:
        cursor = conn.execute(query, args)
    return cursor.rowcount

    Ahora, si le pasamos una conexión, ejecuta la query sin hacer commit. Si no le pasamos nada, funciona como antes.

    Vamos a modificar send_money() para que reciba la conexión y solo ejecute las operaciones. El control de la transacción (commit/rollback) lo hará quien la llame:

    def send_money(sender, receiver, amount, conn):
    rowcount = ejecutar_sql(
        "UPDATE cuentas SET saldo = saldo - ? WHERE nombre = ? AND saldo >= ?",
        (amount, sender, amount), conn
    )
    print(f"Filas afectadas: {rowcount}")
    if rowcount == 0:
        print("No se pudo realizar la transferencia")
        return
    raise Exception("Alguien se tropezó con el cable del server")
    ejecutar_sql(
        "UPDATE cuentas SET saldo = saldo + ? WHERE nombre = ?",
        (amount, receiver), conn
    )

    send_money() solo ejecuta las queries sobre la conexión que le pasamos. Si algo falla, la excepción sale de la función y llega al except del caller, que deshace todo con rollback().

    Cambiamos también la llamada a send_money para gestionar los errores que puedan salir:

    conn = sqlite3.connect("banco.db")
try:
    send_money("Javier", "Maria", 100, conn)
    conn.commit()
except Exception as e:
    conn.rollback()
    print(f"Error: {e}")
    print("Transferencia cancelada")
finally:
    conn.close()

    Este es el código completo, ahora con la transacción y la gestión de errores:

    import sqlite3

conn = sqlite3.connect("banco.db")
with open("schema.sql", "r") as f:
    schema = f.read()

conn.executescript(schema)
conn.close()


def ejecutar_sql(query, args, conn=None):
    if conn is None:
        conn = sqlite3.connect("banco.db")
        cursor = conn.execute(query, args)
        conn.commit()
        conn.close()
    else:
        cursor = conn.execute(query, args)
    return cursor.rowcount


ejecutar_sql("INSERT OR IGNORE INTO cuentas (nombre, saldo) VALUES (?, ?)",
         ('Javier', 300))


ejecutar_sql("INSERT OR IGNORE INTO cuentas (nombre, saldo) VALUES (?, ?)",
         ('Maria', 0))


def send_money(sender, receiver, amount, conn):
    rowcount = ejecutar_sql(
        "UPDATE cuentas SET saldo = saldo - ? WHERE nombre = ? AND saldo >= ?",
        (amount, sender, amount), conn
    )
    print(f"Filas afectadas: {rowcount}")
    if rowcount == 0:
        print("No se pudo realizar la transferencia")
        return
    raise Exception("Alguien se tropezó con el cable del server")
    ejecutar_sql(
        "UPDATE cuentas SET saldo = saldo + ? WHERE nombre = ?",
        (amount, receiver), conn
    )


conn = sqlite3.connect("banco.db")
try:
    send_money("Javier", "Maria", 100, conn)
    conn.commit()
except Exception as e:
    conn.rollback()
    print(f"Error: {e}")
    print("Transferencia cancelada")
finally:
    conn.close()

    ¿Cómo funciona?

    1. conn = sqlite3.connect("banco.db") - Abrimos la conexión
    2. conn.execute(...) - Ejecutamos las queries
    3. conn.commit() - Si todo va bien, guardamos los cambios
    4. conn.rollback() - Si hay error, deshacemos todo
    5. conn.close() - Cerramos la conexión

    La clave es que hasta que no hacemos commit(), los cambios no son permanentes. Si hacemos rollback(), todo vuelve al estado anterior.

    Nota: ejecutar_sql() simplifica el código y ayuda a ejemplificar el problema de la transacción, pero no es una buena práctica usarla en una aplicación real.

    Cuando no pasamos una conexión previamente creada, abre una conexión nueva y hace commit de forma implícita, sin que controlemos el momento. Lo normal en producción es compartir una única conexión (o usar un pool) y gestionar las transacciones de forma explícita.

    Resumen

    Las transacciones nos dan atomicidad: o se ejecutan todas las operaciones o no se ejecuta ninguna. Esto es fundamental para mantener la integridad de los datos en operaciones que implican múltiples pasos.
