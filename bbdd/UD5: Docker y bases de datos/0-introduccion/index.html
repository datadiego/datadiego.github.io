    Introducción

    En el tema anterior hemos configurado un servidor MySQL en nuestro sistema y hemos visto como empezar a usarlo.

    Si ya hemos configurado nuestro servidor como queremos, y necesitamos desplegarlo en otro sistema, bien sea un VPS en la nube, en un rack de servidores físico en una empresa, u otro dispositivo, tendríamos que repetir todos esos pasos para tener el mismo comportamiento del servicio.

    Gran parte de la configuración podriamos simplemente copiarla mediante ssh al nuevo sistema y archivos .sql que vuelvan a recrear, por ejemplo, los usuarios con permisos que deseamos. Pero esto no escala fácil, si el día de mañana necesitamos desplegarla en otro, volveremos a tardar mucho tiempo en realizarlo y además se volverá muy tedioso.

    También facilita mucho el desarrollo de aplicaciones con bases de datos, imagina que estás trabajando en desarrollar dos aplicaciones que usan mysql:

    • Una aplicación de una red social
    • Una aplicación para una clínica veterinaria

    Sin docker, tienes dos opciones:

    1. Tienes un servidor mysql centralizado donde desarrollas, mezclando usuarios, permisos, bases de datos y configuraciones.
    2. Tienes dos maquinas virtuales dedicadas solo a mysql, idealmente usarias una version de tu distro de servidor para que sea super ligera.

    En el primer caso es un caos, y cuando quieras lanzar a producción la base de datos será doloroso llevarte todo al sistema que vaya a ejecutar la base de datos, muy posiblemente el propio desarrollo sea complicado, ya que tendrás múltiples cosas mezcladas y no siempre podrán convivir bien.

    En el segundo tienes orden, pero tardarás mucho en configurarlas y tendrás que hacerlo a mano, además, cualquier cambio te obliga a trabajar en otro sistema y consumirá muchos más recursos por mucho que uses una version servidor de una distro.

    Docker elimina todos esos problemas, trabajas en tu sistema operativo, aislas todo lo que necesites de un proyecto concreto con mysql (u otra base de datos) en un directorio. Si necesitas cambiar un aspecto de su configuración solo lo cambias ahí, sin afectar al resto, y cuando no vas a desarrollar simplemente borras el entorno, al arrancar de nuevo todo se volverá a crear desde cero con la misma configuración.

    Docker

    Docker nos permiten crear contenedores de aplicaciones.

    Es una aplicación nativa en Linux, y es donde mejor funciona, pero puedes usarla tanto en Windows como en Mac. Con el tiempo se han convertido en un estándar de la industria, aunque compite con otras similares como Podman o Nix, y dependiendo del proyecto, pueden ser más interesantes.

    Imagina un contenedor como una caja aislada de tu sistema operativo, que contiene todo lo que un software necesita para funcionar. De forma que puedas llevarte ese contenedor a otro sistema y funcione exactamente igual. Independientemente del sistema operativo que use y en el que se esté desarrollando.

    Docker en realidad se basa en un comando que tienes disponible en Linux, chroot, que nos permite cambiar la raiz de nuestro sistema por otro directorio, Docker crea un entorno Linux básico, y cambia la raiz a ese directorio para poder aislar las aplicaciones.
