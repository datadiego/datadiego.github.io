    D1

    D1 es un servicio de cloudflare de base de datos, que puede funcionar junto a sus workers, que funcionan como FaaS (Functions as a Service).

    Los workers siguen un modelo serverless, no tienes un VPS al que conectarte, y no hay un servicio corriendo continuamente, cuando llamas a un endpoint del backend, cloudflare ejecuta el código del worker, y una vez termina el proceso se cierra.

    Si sabes usar SQLite, D1 en cuanto a sintaxis es igual, pero tendremos un tooling diferente.

    Creación de un proyecto

    Usaremos hono como backend, junto a pnpm como runtime.

    Para crear tu proyecto:

    pnpm create hono@latest
#tambien puedes usar otro runtime
bun create hono@latest
npm create hono@latest

    Selecciona el template cloudflare-workers.

    Instala las dependencias con pnpm install en el directorio que se crea tras el proceso.

    Tooling

    Casi toda la gestión se hará mediante wrangler, viene ya instalada como dependencia de desarrollo en tu proyecto.

    Necesitarás usar npx wrangler para interactuar con los diferentes servicios que puedes usar.

    Primero haz npx wrangler login --device para conectarte a tu cuenta.

    Creando la base de datos D1

    Ejecuta:

    npx wrangler d1 create testing

    Esto creará una base de datos llamada testing, puedes comprobar si se ha creado con:

    Para usarla en tu proyecto, descomenta esta linea en tu wrangler.jsonc:

      "d1_databases": [
    {
      "binding": "my_db",
      "database_name": "my-database",
      "database_id": ""
    }
  ],

    Sustituye database_name por el nombre de tu base de datos, y database_id por el id de la base de datos que acabas de crear.

    En cuanto a binding, es el nombre por el que accederás mediante código a tu db, puedes poner el que quieras, DB es muy común.

    Migraciones

    El concepto de migraciones es una forma de trabajar con bases de datos en la que en lugar de tener un archivo enorme de sql, vamos dividiendo en múltiples archivos conforme la base de datos va evolucionando.

    En nuestro proyecto tendremos un directorio llamado migrations, donde iremos añadiendo las modificaciones necesarias conforme la aplicación avance, siguiendo la siguiente nomenclatura:

    0001-create-users.sql
0002-add-email.sql
0003-create-messageboard.sql

    D1 podrá darte información de en qué estado se encuentra de la migración, y cuales hemos aplicado o faltan por incluir en la db.

    Funcionando en local

    D1 nos permite desarrollar en local sin tocar la base de datos en producción que acabamos de crear. Vamos a usarla para crear una base de datos sencilla a través de migraciones.

    Crea un directorio migrations, dentro, crea 0001-create-users.sql con una tabla básica:

    CREATE TABLE users (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  username TEXT NOT NULL UNIQUE,
  password TEXT NOT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

    Para crear la base de datos local:

    npx wrangler d1 migrations apply <nombredb> --local
npx wrangler d1 migrations apply testing --local

    Si te preguntas donde está tu base de datos local, es en el directorio .wrangler:

    Crea una nueva migración llamada 0002-add-some-users.sql:

    INSERT INTO users (username, password) VALUES 
('admin', 'adminpass'),
('user0', 'user0pass');

    Y vuelve a realizar una migración como hemos visto antes.

    Creando un backend simple

    Crea esto en tu src/index.ts:

    import { Hono } from 'hono'

const app = new Hono<{ Bindings: CloudflareBindings }>()

app.get('/', (c) => {
  return c.text("Hola desde Hono!")
})

app.get('/users', async(c) => {
  const users = await c.env.DB.prepare('SELECT * FROM users').bind().all()
  return c.json(users)
})

export default app

    Deploy del worker

    Tienes dos opciones, o mediante un repositorio de Github, o con npx wrangler deploy.

    Mediante repositorio

    1. Crea un repositorio en github con tu proyecto
    2. En cloudflare, ve a Workers y Pages
    3. Selecciona Crear aplicacion
    4. Selecciona Github, busca el repositorio y deja que cree la aplicación.

    Lo bueno de este método es que tenemos un pipeline de CICD, cada vez que mandes cambios a tu rama principal en github, se actualizará en cloudflare.

    Mediante wrangler

    Simplemente ejecuta npx wrangler deploy:
