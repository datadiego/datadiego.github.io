    Gestionando dotfiles

    Ya sabemos como funciona stow, ahora vamos a ver como empezar a usarlo con nuestros archivos de configuración.

    Creando tu directorio de dotfiles

    Crea el directorio donde almacenarás tus dotfiles, a mi gusta ~/.dotfiles y mantenerlo oculto en mi home, pero puedes usar el nombre que prefieras.

    pruebas@fedora:~$ mkdir .dotfiles

    Luego inicia un repositorio en el para poder versionar tus dotfiles.

    pruebas@fedora:~$ cd .dotfiles/
pruebas@fedora:~/.dotfiles$ git init

    Nuestro primer dotfile

    Vamos a registrar nuestro primer dotfile, tu archivo ~/.bashrc.

    Para ello, necesitamos crear esta estructura de directorios en el directorio ~/.dotfiles:

    .
└── bash
    └── .bashrc

    Para ello:

    pruebas@fedora:~/.dotfiles$ mkdir bash
pruebas@fedora:~/.dotfiles$ cp ~/.bashrc bash/

    Sin embargo, cuando intentes hacer stow bash, este provocará un error:

    pruebas@fedora:~/.dotfiles$ stow bash
WARNING! stowing bash would cause conflicts:
  * cannot stow .dotfiles/bash/.bashrc over existing target .bashrc since neither a link nor a directory and --adopt not specified
All operations aborted.

    Por seguridad, stow no sobreescribe archivos existentes, por lo que debes eliminar los archivos originales antes de hacer stow.

    pruebas@fedora:~/.dotfiles$ rm ~/.bashrc
pruebas@fedora:~/.dotfiles$ stow bash
pruebas@fedora:~/.dotfiles$ ls -la ~
total 16
drwxr-xr-x. 1 pruebas pruebas 122 sep 18 15:43 .
drwxr-xr-x. 1 root    root     46 sep 18 11:50 ..
-rw-------. 1 pruebas pruebas 133 sep 18 12:28 .bash_history
-rw-r--r--. 1 pruebas pruebas  18 ene 16  2026 .bash_logout
-rw-r--r--. 1 pruebas pruebas 144 ene 16  2026 .bash_profile
lrwxrwxrwx. 1 pruebas pruebas  22 sep 18 15:43 .bashrc -> .dotfiles/bash/.bashrc
drwxr-xr-x. 1 pruebas pruebas  14 abr 22 16:01 .config
drwxr-xr-x. 1 pruebas pruebas  16 sep 18 15:39 .dotfiles

    Listo! Ya tienes tu archivo ~/.bashrc gestionado por stow, puedes hacer commit para guardar los cambios en tu repositorio.

    Desde ahora, cuando actualices tu archivo bashrc, bien desde ~ o en ~/.dotfiles, los cambios estarán sincronizados automáticamente.

    Sincronizando nuestro editor de código

    Mantener tu misma configuración en el editor de código que uses es una de las opciones más cómodas que tiene tener un directorio de dotfiles, mantienes tus mismos keybindings y settings.

    Vamos a probarlo con zed, la configuración por defecto de .config/zed/ no tiene gran cosa, si cambiaste tu tema tendrás algo como esto en settings.json:

    {
  "ui_font_size": 16,
  "buffer_font_size": 15,
  "theme": {
    "mode": "dark",
    "light": "One Light",
    "dark": "Gruvbox Dark Hard",
  },
}

    Si añadiste atajos personalizados, tendrás un keybindings.json:

    [
  {
    "context": "Workspace",
    "bindings": {
      // "shift shift": "file_finder::Toggle"
      "ctrl-ñ": "workspace::ToggleBottomDock",
      "ctrl-;": "workspace::ToggleBottomDock"
    },
  },
  {
    "context": "Terminal",
    "bindings": {
      "ctrl-ñ": "workspace::ToggleBottomDock",
      "ctrl-;": "workspace::ToggleBottomDock"
    },
  },
  {
    "context": "AcpThread > Editor",
    "bindings": {
      "ctrl-ñ": "workspace::ToggleBottomDock",
      "ctrl-;": "workspace::ToggleBottomDock"
    },
  },
  {
    "context": "Editor",
    "bindings": {
      "ctrl-ñ": "workspace::ToggleBottomDock",
      "ctrl-;": "workspace::ToggleBottomDock",
      "alt-z": "editor::ToggleSoftWrap"
    },
  },
  {
    "context": "Workspace",
    "unbind": {
      "ctrl-~": "workspace::NewTerminal"
    }
  }
]

    Puedes copiar esta configuración, es básica pero tiene un keybinding muy útil, hacer toggle de la terminal integrada del editor con ctrl + ñ

    En nuestro directorio de dotfiles, tendremos que crear esta estructura, copiando el contenido de tu configuración:

    zed/
└── .config
    └── zed
        ├── keymap.json
        ├── settings.json
        └── themes

    De nuevo, tendrás que borrar la configuración original antes de probar a hacer stow con tu configuración nueva.

    Finalizando

    stow no tiene mucho más que hacer, tendrás que ir creando los directorios que configuraciones que quieras conservar entre equipos, y actualizando tu repositorio con los cambios.

    Una vez has hecho stow de tus dotfiles en dos equipos o más, cuando modifiques la configuración de un equipo, simplemente añade los cambios al repositorio, haz commit, y cuando vuelvas al otro equipo al hacer pull todo se actualizará con la última versión de tus dotfiles.

    Más adelante automatizaremos que se haga stow de todos tus dotfiles cuando estés en un equipo nuevo, de esta forma no tendras que ir ejecutando stow <directorio> de cada una de tus aplicaciones.
